현재 구현의 페이스 기준은 빈 필드를 포함해 다음과 같다.

```text
[0, 0, 2, 4, 8, 10, 12, 15, 17, 19, 22, 25, 28, 30, 33, 36, 38, 40]
```

1–9가방은 SAO·Sarcelle 중 낮은 진행을 사용한다. Sarcelle 10가방의 루프 재구축과 그 뒤에 남는 누적 지연을 추가 준비 여유로 삼지 않으므로, 10가방 이후는 SAO의 연속 진행을 사용한다. 배치 수 n과 예산 B에 대해 `17n/B` 위치를 보간하고 목표 스핀 `G/40`을 곱한다. `PACE_NEAR_SLACK=1`이고 허용 차이는 `1 + max(0,B−n)/B`다. 40스핀·119미노의 7가방 기준은 15이며, 13스핀은 이 페이스 검사에서 제외하고 14스핀은 허용한다. 현재 가방 안에서는 남은 재료가 만들 수 있는 스핀 상한을 더해 가방 끝에 비교하므로, 가방 후반에 몰린 스핀을 현재 lock의 할당량으로 자르지 않는다. 첫 가방과 실제 목표 달성은 보호한다. 공개 도식은 진척 참고자료이며 현재 물리·제한된 홀드 정책의 실행 인증은 아니다.

개선이 이어지는 일반 경계의 생성 예산은 3–8회, 페이스가 늦지만 적격인 경계는 3–4회, 첫 가방 경계는 2–3회다. 검증된 자식의 스핀 증가 또는 같은 증가량에서의 필드 품질이 4회 이상 개선되지 않으면 다음 재방문은 생성 1회·설정 폭의 1/4로 줄인다. 새 경계와 생산적인 경계는 설정 폭의 절반 또는 전폭을 사용하며 최소 폭은 4다. 후속 경계의 시도 수만으로 폭을 넓히지 않는다. 빈 출발점의 새 첫 가방 탐색은 별도로 유지하고, 긴 경로 검사와 품질 열세의 예외도 좁은 예산을 사용한다.

## 1. 재설계 방향

v2의 장기 설계는 다음 흐름을 목표로 한다. 완전한 제약 전파와 전체 공간의 branch-and-bound 소진은 현재 구현으로 주장하지 않는다.

**국소 스핀 목표 생성 → 구조·채움·재고 제약 전파 → 비용 및 성공률 상한 검사 → 필요한 배치의 역방향 도달성 확인 → 고정 가방 P7 인증 → 가방 경계의 깊이 우선 branch-and-bound**

최초 UCT에서 계수와 탐색 폭만 바꾸는 작업으로 취급하지 않는다. 24행 필드의 모든 배치 위치를 먼저 생성하는 전단을 교체하는 것이 핵심이다. MCTS는 v2 주 제어기에서 제외한다. 현재 구현은 빠른 표면 배치와 역방향 스핀 목표 확인을 먼저 사용하고, 유효 가방을 찾으면 자식 경계를 우선 연장한다. [집중 탐색과 병렬 실행](FOCUSED_SEARCH.md)에 현재 구현과 남은 범위를 구분한다.

Alpha–Beta에서 가져오는 것은 하한·상한에 의한 조기 중단, 좋은 수의 우선 탐색, 반복 심화, 전이표, 현재 최선 수순의 재사용이다. 확률적 미노 공급을 최악의 수를 고르는 상대방으로 바꾸지는 않는다.

이 문서는 이전 설계 중 다음 내용을 대체한다.

- 상단 sky envelope를 허용하는 물리 모델.
- 전방 전체 도달 위치 생성 후 beam/UCT로 선택하는 주 탐색.
- 모든 가방에 반복 적용하는 무클리어 setup 편향.
- 현재 최선 미완성 후보를 실제 탐색 중 필드처럼 사용하는 GUI 상태.
- Clearra의 색상·레이아웃을 참고한 자체 컴포넌트만으로 GUI 재사용을 완료했다고 보는 기준.

## 3. 최초 코드 감사에서 확인한 병목 — 역사적 기록

출처: [Neyra search.rs](https://github.com/daejunnom/Neyra/blob/2baf90f97eb60994b35f570198c5e25d64ad0606/crates/neyra-core/src/search.rs).

### 3.1 준비 단계 편향이 이후 가방에도 적용된다

최초 검토본의 setup은 generation_rounds % 3 != 2로 정해졌다. setup에서는 줄이 지워지는 후보를 모두 버렸다. 따라서 **모든 깊이에서 제안 라운드의 2/3가 무클리어 전용**이었다. 이는 채택된 결과 가방의 2/3가 무클리어라는 뜻은 아니지만, 생산적인 후속 스핀을 찾는 계산을 크게 줄인다. 현재는 이 전용 라운드를 빈 필드의 첫 가방에만 적용한다.

첫 가방의 높은 구축률을 위한 준비와 이후의 필요에 따른 구조 보수는 분리한다. 첫 가방 0스핀은 우선 탐색할 분기이며, 모든 후보의 필수 조건으로 고정하지 않는다.

### 3.2 가장 비싼 계산을 너무 일찍 한다

최초 검토 커밋의 전단은 cache.locks(board, piece)로 전체 reachable_locks를 구한 후 중간 후보를 최대 32개, 완성 후보를 8개로 줄인다. 후단의 역방향 목표 검증이 있어도 전단 비용은 이미 지출된다.

새 전단에서는 스핀 목표·필요 셀·재고로 후보를 제한한 다음, 살아남은 특정 target pose에 대해서만 도달성을 확인한다.

### 3.3 기존 하한은 구조를 거의 구분하지 못한다

배치 수를 n, 지금까지 싱글 수를 s, 잔여 셀을 C, 남은 목표를 R=40-s라고 하자. 빈 필드에서 시작하면:

    C = 4n - 10s

최초 검토본의 기초 하한은 다음 형태이며 현재도 안전한 필요조건으로 유지한다.

    h = max(R, ceil(max(0, 10R-C) / 4))

따라서 전체 비용 하한은:

    n+h = max(n+40-s, 100)

이다. 35개를 놓고 3스핀만 한 상태도 이 하한은 100개다. 이 식은 유지해야 하는 안전한 기초 하한이지만, 이후 스핀을 만들 수 없는 지형을 골라내는 강한 평가가 아니다.

### 3.4 실시간 필드가 실시간 상태가 아니다

최초 검토본의 current는 실제 처리 노드가 아니라 기록이 개선될 때만 바뀌는 미완성 후보였다. 당시 UI 재개 시 탭·과거 프레임도 그대로 남았다. 현재의 최신 경로 기본 화면, 선택한 탐색 관찰과 기록 갱신 계약은 [집중 탐색](FOCUSED_SEARCH.md)을 따른다.

## 4. 스핀 생산성을 보는 자원 모델

한 가방은 28셀을 공급한다. 그 가방의 싱글 수가 g이면:

    C_next = C + 28 - 10g

| 가방의 스핀 싱글 | 잔여 셀 변화 |
| ---: | ---: |
| 0 | +28 |
| 1 | +18 |
| 2 | +8 |
| 3 | -2 |
| 4 | -12 |

현재 기본 119개는 17가방이며, 첫 가방이 0스핀이면 이후 평균 2.5스핀이 필요하다. 최초 설계의 예시인 112개는 16가방으로 이후 평균 40/15 = 2.667스핀이 필요하다. 4스핀 가방은 유용하지만 이전 셀을 12개 소비하므로 모든 후속 가방을 4스핀 이상으로 강제하지 않는다.

5가방·3스핀은 C=110이며, 112개까지 남은 11가방에 37스핀, 평균 3.364가 필요하다. 이는 우선순위를 낮추거나 후속 구조를 더 깊게 검사할 근거다. **평균이 낮다는 사실만으로 불가능을 증명하지 않는다.** 저장된 셀을 남은 예산 안에 소비할 수 있는 구조인지가 중요하다.

설계상 각 가방은 다음 중 하나 이상의 역할을 가진다.

- 다음 스핀에 필요한 지지 셀을 만든다.
- 준비한 국소 구조를 소비해 여러 싱글을 만든다.
- 다음 작업 영역으로 넘어가는 형태를 만든다.

반복 주기를 고정하지 않는다. 0·1스핀 가방도 허용하되, 생성기에서는 특정 후속 목표의 미충족 요구를 줄이는 배치를 우선한다. 목적 없는 적재를 별도 setup 라운드로 대량 생산하지 않는다.

## 5. 정확한 물리 계약

### 5.1 공식 규칙 자료와 탐색용 등가 최적화를 구분

최상위 물리 기준은 [공식 tetrio.js](https://tetr.io/js/tetrio.js)의 SRS+ 데이터와 ComputeKick의 원점 우선 처리다. 2026-10-31 원문 SHA-256은 다음과 같다.

    9e57c958c43520deb5dd91f5e1773bf779bfb91e7d273dc8494a93a3a0866d2f

공식 자료는 90도 전이 56개와 180도 전이 28개, **84개 전이**다. O의 disallow_kick은 추가 offset을 금지하지만 원위치 회전은 먼저 검사하므로, O 180도가 원문에 없다는 설명은 잘못이다.

그러나 이 사실이 탐색 그래프에 O 180도 간선을 추가해야 한다는 뜻은 아니다. 표준 O의 네 방향은 점유 셀이 같고 두 원위치 90도 회전으로 180도를 대체할 수 있다. 정확한 입력 횟수·lock reset·입력 타이밍이 주 제약이 아닌 이번 배치 탐색에서는 **Clearra Rust의 기존 80전이 최적화를 유지**한다. 공식 84개를 보관하는 자료와, 등가 간선을 생략한 runtime 프로필을 분리한다.

I 180도는 다르다. 원문은 최초 (0,0)을 암묵적으로 시도하고 이후 하나의 offset을 검사하므로 총 두 후보다. 기존 Rust 값이 맞으며 C의 여섯 후보는 순서와 값이 달라 first-success 결과와 최종 도달 가능한 점유 셀까지 바꿀 수 있다. 따라서 C I180만 두 후보로 정정하고, C 기본 실행 경로에 canonical Rust의 검증된 80전이 descriptor를 전달한다. O를 제외한 원문과의 수치·순서는 정확히 일치시킨다.

[공식 규칙 fixture](../crates/neyra-core/tests/fixtures/tetrio_srs_plus_standard_tetromino_kicks.json)와 [Neyra 생성기](../scripts/generate-srs-plus.py)를 버전 관리한다. fixture는 원문의 y축을 변환하고 최초 (0,0)을 명시한 84전이를 보존한다. 전체 tetrio.js는 제품 저장소에 넣거나 실행하지 않는다.

완료한 원문·SRS+ 대조는 탐색 평가나 화면만 바꾸는 작업과 Pages CI에서 반복하지 않는다. fixture·생성기·회전 의미를 변경할 때 해당 대조를 다시 수행한다. 필요한 제품 fixture와 생성기는 유지하며, 1회성 감사 스크립트·실험·결과는 저장소 밖에 보관한다.

Neyra의 물리 회전·명시적 replay는 이 84전이 자료를 사용한다. 별도의 빌드 탐색 정책으로 O 스핀을 제외하고, 같은 점유 셀을 만드는 O의 회전 후보는 대표 방향으로 축약할 수 있다. reference move generator와 명시적 회전 replay를 유지하여 이 최적화의 기하학적 동등성을 확인한다. O 이외 미노에서는 동일 점유 셀이라도 다음 kick·스핀 이력이 다를 수 있으므로 rotation 상태를 전역적으로 합치지 않는다.

RulesFingerprint에는 upstream 자료, descriptor, 미노 좌표·원점, 순서 있는 kicks, 허용 입력, spawn, 천장, O 스핀 제외와 drop 정책을 포함한다. 물리 계약이 달라지면 물리·P7 인증 캐시를 재사용하지 않는다. 등가 최적화만 바뀐 경우에는 계약의 동등성을 먼저 확인하고 불필요한 자산 무효화를 피한다.

### 5.2 24행은 실제 셀의 사망 경계

좌표는 아래에서 y=0..23이다. 실제 네 셀 중 하나라도 y>=24인 **선택된 이동 결과**는 CeilingDeath다.

    StepOutcome = Moved(Pose) | Blocked | CeilingDeath

회전은 먼저 Clearra의 순서대로 벽·바닥·기존 블록 충돌을 검사한다. 최초로 물리적으로 성립하는 kick이 상단을 넘으면 사망으로 끝낸다. 그 kick을 실패한 것처럼 건너뛰고 뒤의 kick을 사용하지 않는다.

미노 matrix 원점이 24 이상이라는 이유만으로 제거하지 않는다. 빈 padding 때문에 원점과 실제 점유 셀의 최고 높이는 다를 수 있다. 회전별 min_dy/max_dy로 네 셀의 범위를 빠르게 검사한다.

천장 사망 영역은 다음에 사용하지 않는다.

- T의 점유 corner를 늘리는 가상의 블록.
- all-spin immobility를 만족시키는 지지벽.
- 기존 SRS+에 없던 ceiling kick을 만드는 충돌벽.

즉 이동 결과의 사망과 스핀 판정용 충돌은 구분한다. 현재 sky envelope는 제거하고 어떤 순·역방향 탐색 상태도 사망 영역의 실제 셀을 보관하지 않는다.

### 5.3 역방향 도달성

목표 상태는 pose뿐 아니라 스핀을 성립시키는 마지막 동작 상태를 포함한다. 역방향 후보 전이는 항상 같은 정방향 판정기로 확인한다.

- inverse rotation: 앞선 kick까지 포함한 first-success를 재검증한다.
- inverse Sonic Drop: 정방향 Sonic이 정확히 목표 landing까지 내려와야 한다.
- 한 칸 낙하를 역전이로 추가하지 않는다.
- 스핀 후 실제로 내려간 Sonic이 스핀 상태를 보존한다고 가정하지 않는다.
- 이미 지면에 있는 0거리 drop과 실제 이동한 drop을 구분한다.

종료 조건은 실제 spawn에서 낙하 없이 도달 가능한 entry 상태다. 빈 필드에서 만들었던 preset 좌표가 있다는 이유만으로 현재 필드에서도 접근 가능하다고 보지 않는다. 사전 계산한 geometry 후보와 현재 필드의 no-drop 도달성 검사를 결합한다. 높은 곳에 있다는 이유만으로 모든 pose를 source로 인정하는 sky seed는 사용하지 않는다.

## 6. 구조 문법: 양측 적재와 작은 스핀 작업 영역

### 6.1 자료에서 가져올 수 있는 구조적 관찰

Mechanical Hearts는 두 주요 패턴과 높이에 따른 단계 전환을 명시한다. Sarcelle에는 실제 Naga Eyes 경로와 스핀 묶음을 한 가방 늦추는 경로가 있다. 이는 긴 빌드를 독립적인 낱개 배치보다 **작은 형태와 그 사이의 전이**로 다루는 방향을 뒷받침한다.

다만 원문의 멀티라인, 중력 대기, 다음 가방으로 넘기는 홀드, 반복은 이번 모델에 그대로 옮길 수 없다. 문서 그림의 구멍 수를 전수 측정하지 않았으므로 모든 좋은 빌드의 구멍 상한이 1개나 2개라는 주장은 하지 않는다.

참조: [Mechanical Hearts](https://harddrop.com/wiki/Mechanical_Hearts), [Sarcelle](https://harddrop.com/wiki/Sarcelle), [TeaL](https://harddrop.com/wiki/TeaL), [Stickspin](https://harddrop.com/wiki/Stickspin).

### 6.2 표현

물리적 원본은 항상 정확한 24개 row mask다. 별도 구조 분석값으로 다음을 둔다.

- 좌우 저장부의 열 높이와 표면.
- 스핀 작업 영역의 중심·폭·실제 마스크.
- 활성 포켓과 다음 전이의 미충족 요구.
- 반드시 채워야 할 셀과 비워 두어야 할 셀.
- 지지 셀의 필요 시점과 담당 미노 집합.
- 포켓을 소비할 수 있는 미노·스핀 형태·마감 단계.

중심을 5열로 고정하지 않는다. 4+1+5와 5+1+4 모두 허용할 수 있으며, 작업 영역의 지붕·턱은 양측으로 걸칠 수 있다. 가운데 한 열을 영구적인 배치 금지 열로 두지 않는다.

초기 좁은 프로필은 양측 저장부에서 의도하지 않은 매몰 빈칸을 허용하지 않고, 복잡한 빈칸은 등록된 작업 영역과 소비 계획이 있는 포켓 안에 제한한다. 모든 lock 직후 이 조건을 검사하되, 명시된 임시 포켓은 예외로 인정한다. 가방 말에는 완료된 포켓을 제거하고 남은 포켓의 계약을 다음 가방에 전달한다.

활성 포켓 1곳과 작은 보조 포켓 1곳 같은 초기 상한은 **탐색 범위를 정하는 설정**이다. 전체 테트리스 공간에 대한 불가능 정리가 아니다. 정체 시 포켓 범위·상대 높이·초기 준비 길이 등을 점진적으로 넓힌다.

### 6.3 의도된 구멍은 처리 의무를 가진다

포켓은 단순한 감점 대상이 아니다. 예를 들어 다음 정보를 가진다.

    PocketContract:
      required_filled
      required_empty
      first_kick_failure_clauses
      allowed_finishers
      phase / logical-row requirements
      inventory_requirements
      successor_structure

어떤 미노를 먼저 놓아야 하는지와 어떤 미노가 놓이면 진입이 막히는지를 구분한다. 지지 조건이 A 또는 B라면 이를 A와 B 모두 필요로 바꾸지 않는다.

일반 빈칸 flood fill, 열별 구멍 수, 표면 거칠기는 빠른 특징값이다. 그것만으로 미노의 회전·킥 도달 불가능을 증명하지 않는다.

### 6.4 상태를 손실 있게 합치지 않는다

상단 몇 행이나 열 높이만으로 전이표 키를 만들지 않는다. 삭제될 아래 행, 지지 블록, 절대 바닥·천장 거리가 미래 경로를 바꿀 수 있다.

상대 높이로 정규화한 키는 국소 기하학 후보의 재사용에 사용할 수 있다. 물리 경로 인증에는 정확한 전체 필드와 경계 거리를 포함한다. 해시가 같더라도 정확한 필드를 비교한 뒤 지배 가지치기를 수행한다.

## 7. 후보 생성: 다음 스핀에서 필요한 배치를 역으로 구성

### 7.1 빈 필드의 첫 가방부터 목표를 준다

첫 가방을 자유롭게 쌓고 좋은 필드를 나중에 찾지 않는다. 우선 **두 번째 가방의 생산적인 국소 스핀 목표**를 만든 다음, 이를 가능하게 하는 첫 가방 말의 지지·빈 공간 조건을 역으로 구한다.

우선 탐색 분기는 첫 가방 0스핀과 다음 가방의 3~4스핀 목표다. 그러나 이것은 우선순위다.

- 첫 가방에서 Spin Single을 포함하는 별도 생성 분기가 있어야 한다.
- 다음 가방 2스핀이나 더 긴 준비도 확장 프로필에서 생성할 수 있어야 한다.
- 실제 생성기가 없다면 문서에만 “허용”이라고 적지 않는다.

첫 가방 무클리어 분기는 정확히 7종 28셀의 packing 문제로 줄일 수 있다. 첫 가방에도 소거가 있는 분기는 아래의 단계·논리 행 모델을 사용한다.

받침마다 언제 필요한지, 첫 가방이 제공해야 하는지, 두 번째 가방의 앞선 미노가 제공하는지를 구분한다. 이후에 생길 받침까지 첫 가방에 모두 요구하면 유효 경로를 없애거나 진입로를 막는다.

### 7.2 국소 스핀 목표

한 번의 스핀 목표는 다음 조건을 가진다.

1. 목표 미노의 최종 네 셀과 orientation.
2. 정확히 한 행을 완성하는 채움 조건.
3. 스핀 판정을 위한 corner 또는 immobility 조건.
4. 직전 회전과 선택된 SRS+ kick.
5. 그보다 먼저 검사되는 kick 후보들의 실패 조건.
6. 진입·회전 중 비어 있어야 하는 셀.
7. 소거 뒤 이어질 구조의 요구.

앞선 kick의 실패는 보통 “이 후보의 셀 중 적어도 하나가 막힘”이라는 논리합이다. 모든 후보를 하나의 occupied mask로 합치는 방식으로 처리하지 않는다. 벽·바닥에 의한 실패는 상수 조건이며, 상단 사망은 뒤 kick으로 넘어갈 수 있는 실패가 아니다.

국소 패턴은 특정 오프너의 여러 가방 수순을 복사해 만들지 않는다. 미노 geometry와 SRS+ 전이에서 생성하고 같은 요구 조건을 합친다.

### 7.3 부족한 셀을 먼저 채운다

목표에 필요한 셀 중 현재 없는 셀을 찾는다. 가장 제약이 큰 셀부터 담당 미노와 배치 후보를 정한다.

- 남은 재고는 7비트로 관리한다.
- 목표 셀을 덮을 수 있는 미노가 없으면 탈락한다.
- 서로 다른 미노를 소비해야 함이 증명된 배치 슬롯들이 같은 유일 미노를 요구하면 matching으로 탈락시킨다.
- must-empty를 침범하거나 다른 배치와 겹치면 탈락한다.
- 지정 영역 밖의 임의 내부 배치는 생성하지 않는다.
- 남는 미노는 양측 표면을 유지하거나 명시된 다음 스핀을 준비하는 곳에 둔다.

side packing의 기하학 후보는 표면·재고별로 캐시할 수 있다. 이 캐시는 실제 spawn 접근 가능성까지 인증한 캐시와 구분한다. 명시적 “스폰에서 회전·수평 이동 후 Sonic” 경로가 성공하면 저렴한 물리 증거로 활용한다.

셀 하나마다 미노 하나를 할당하는 matching은 사용하지 않는다. 미노 하나가 여러 부족 셀과 지지 요구를 동시에 충족할 수 있다. 셀 coverage는 후보 배치 하나가 여러 셀을 덮는 0/1 배치 변수로 표현하고 종류별 사용 횟수·겹침·단계 제약을 함께 둔다. 후보 도메인이 제한된 경우의 실패는 해당 계획·프로필에 한정하며, 누락된 배치까지 포함한 전역 불가능으로 저장하지 않는다.

### 7.4 여러 스핀과 소거를 포함하는 가방

28셀을 정적 필드에 한꺼번에 타일링한 뒤 마지막에 줄을 지우는 방식은 사용하지 않는다. 가방 안에서 여러 번 소거되므로 각 단계의 좌표가 바뀐다.

현재 프로젝트의 논리 행 방식은 보존할 가치가 있다.

- 가방 시작의 행에 논리 ID를 부여한다.
- 삭제된 논리 행 집합을 기록한다.
- 고정된 각 미노 목표는 네 개의 논리 셀을 가진다.
- 실행할 때 아직 삭제되지 않은 논리 행을 실제 높이로 투영한다.
- 투영 결과가 해당 미노의 유효한 pose인지 검사한다.
- 같은 subset이라도 삭제 이력이 달라지면 다른 상태로 둔다.

타깃의 논리 행이 이미 삭제되었다면 그 순서에서 해당 타깃은 불가능하다. 같은 네 셀에 대응하는 회전 상태가 여러 개면 도달성·스핀 판정에서 모두 고려한다. 동시 삭제되는 물리 행은 삭제 전 매핑으로 한꺼번에 논리 행으로 돌린다. 논리 셀 집합은 선행 삭제 뒤 투영해야 실제 미노 모양이 될 수 있으므로, 원래 논리 좌표에서부터 테트로미노로 연결되어 있어야 한다는 조건을 넣지 않는다.

소거로 새로 들어오는 상단 빈 행에도 논리 ID를 줄 수 있다. 이 논리 ID가 24 이상이라는 사실은 실제 셀이 사망 천장을 넘었다는 뜻이 아니다. 천장은 항상 투영한 실제 y=0..23에서 검사한다.

여러 스핀 목표를 작은 묶음으로 생성하고 재고에 맞게 가방을 완성한다. 3~4스핀 후보를 생산할 수 있어야 하지만, 처음부터 모든 종류·높이·중심·kick의 곱집합을 전개하지 않는다. 필요 마스크·빈칸 조건·소거 단계·재고가 같은 요구는 합친다.

## 8. 저렴한 검사부터 비싼 검증까지

후보 처리 순서:

1. 범위·점유 충돌·셀 수·남은 종류 검사.
2. 구조 프로필 검사와 포켓 의무 전파.
3. 목표 셀 coverage 및 재고 matching.
4. 증명된 필수 선행 조건의 공급 성공률 상한.
5. 남은 lock 비용의 하한.
6. 안전한 완화 모델이 제공하는 미래 스핀 수 상한.
7. 특정 목표 배치에 대한 역방향 도달성.
8. P7 실행 그래프의 점진적 인증.
9. 정확한 공통 가방 경계의 생성.

실패가 발생하면 가능한 한 국소적인 원인으로 저장한다. 예를 들어 특정 시점의 지지 부족과 재고 충돌을 동일 규칙·동일 조건에서 재사용한다. 한 순서에서 막혔다는 이유로 가방 전체의 필수 의존성을 만들지 않는다.

## 9. P7 검증: 물리 경로를 공유하고 상한으로 일찍 중단

### 9.1 현재 공급 계약과 양화 순서

먼저 모든 공급에 일반 배치 막힘 없이 성공 또는 강제 줄 지우기 공급 막힘까지 가는 전략이 있어야 한다. 이 조건은 확률 하한과 독립적이다. 그 위에서 100% 구축의 조건은 다음과 같다.

    어떤 고정 계획 T가 존재하여,
    모든 순열 pi에 대해,
    T를 실행하는 합법적인 경로 e가 존재한다.

계획 T가 순열 밖에 있다. 순열에 맞춰 목표 기하학을 바꾸는 정책을 탐색하면 요구사항을 위반한다. 100%보다 낮은 기준에서는 일반 배치 조건을 유지하면서 실제 종료한 순열 집합의 크기를 계산한다. 첫 빈 가방의 허용된 방향 선택은 2,520개 대칭 쌍 안에서 판정하고, 이후 방향은 고정한다.

### 9.2 실행 그래프와 지연 정밀화 설계

현재 구현은 고정 계획의 물리 실행 그래프를 공유한 뒤 제한된 홀드 언어로 공급을 검사한다. 아래 Unknown/Legal 집합과 비트셋 정밀화는 후속 설계이며 모두 구현된 상태는 아니다. 노드 키의 최소 요소:

    placed_mask
    exact_board
    deleted_logical_rows
    spins
    plan_variant

필요한 입력·스핀 상태는 배치 경로 edge의 인증에 포함한다. 단순히 놓은 미노 subset만 같다는 이유로 노드를 합치지 않는다. 단일 타일링 모드의 variant는 고정값이다.

각 edge 상태는 Unknown, Legal(witness), Impossible이다.

- G+는 Legal과 Unknown을 포함하는 낙관적 그래프다.
- G-는 Legal만 포함하는 인증 그래프다.
- 성공 순열 집합을 C+, C-라고 하면 C- ⊆ 실제 성공 집합 ⊆ C+다.

G+를 만들 때 아직 생성하지 않은 기하학 분기를 없는 것으로 취급하면 안 된다. 저렴한 기하학 그래프를 완결하거나, 미전개 frontier를 가능한 성공으로 남겨 상한을 보수적으로 유지한다. 그래프 크기 제한·시간 제한은 Unknown이다.

### 9.3 제한된 홀드 정책과 향후 비트셋 전파

현재 공급 검사는 `current=q[0]`, `held=Empty`, `cursor=0`, `hold_ready=true`에서 시작한다. 자유로운 최초 홀드를 전제하지 않는다. `ClearOnlyLanguage`는 성공에 이어질 수 있는 실행 간선과, 그 경로에서 줄을 지울 수 있는 미노를 함께 보관한다.

- 일반 배치 간선은 현재 active 미노로만 실행한다.
- 빈 홀드에 보류할 수 있는 것은 성공 가능한 후속 경로의 줄 지우기 후보뿐이다. 실제 홀드 미노를 꺼내 배치할 때에는 정확히 한 줄을 지워야 한다.
- 현재 미노를 홀드에 남기는 교환도 같은 제한을 지킨다. 다만 그 배치가 목표를 달성하고 즉시 종료하면 사용하지 않을 현재 미노를 남길 수 있다.
- 빈 홀드 보류는 lock 수가 늘지 않는 명시적 전이다. 새 active 미노의 스폰과 일반 배치 가능성을 확인해야 하며, 보류 전 스핀 막힘으로 임의 종료해 뒤의 일반 배치 실패를 숨기지 않는다.
- 일곱 공급 뒤의 마지막 홀드를 꺼낼 때는 다음 가방의 모든 종류가 스폰 가능해야 한다. 다음 가방의 특정 순서를 미리 선택해 성공률을 높이지 않는다.
- 종료 상태는 다음 미사용 미노의 스폰보다 먼저 인정한다. 부분 종료 계획에 없는 미노는 소비용 배치나 자유 보류의 근거가 되지 않으며, 진행 불가는 줄 지우기 공급 실패다.

같은 공급에서 허용된 전략 중 하나가 성공하면 최소 lock 비용을 기록한다. 성공하지 못하더라도 일반 배치 실패 없이 강제 줄 지우기 공급 막힘에 도달하는 전략이 있으면 일반 배치 조건을 통과한다. 모든 공급이 이 조건을 만족해야 확률 하한과 비용 CDF를 평가할 수 있다.

향후 집합 전파로 바꾸더라도 이 계약을 유지해야 한다. 5,040비트는 79개의 u64에 들어가지만, 상태는 그래프 노드뿐 아니라 별도의 `cursor`·`held`·`hold_ready`를 포함해야 한다. 빈 홀드 전이가 있으므로 배치 깊이만으로 active 위치를 계산해서는 안 된다. 성공 집합과 일반 배치 조건 충족 집합을 각각 전파하고, 최소 lock 비용에는 0비용 홀드 전이를 반영해야 한다.

가방 끝에서 다음 공급을 종류별 조건으로 완화하려면 그 조건부 성공을 다음 가방에 전달하는 다른 모델이 필요하다. 현재의 독립 가방 성공률 곱을 그대로 적용해서는 안 된다.

### 9.4 필요한 경로부터 정밀화 — 후속 설계

C+에서 C-를 제외한 순열 중 하나를 골라 잠재 성공 경로를 찾는다. 그 경로의 Unknown edge만 역방향 물리 검증한다.

Legal 증거 하나는 그 edge를 공유하는 많은 순열을 한꺼번에 인증한다. Impossible 하나는 여러 순열의 잠재 경로를 제거한다. 다만 다른 경로가 살아 있을 수 있으므로 실패 edge를 지웠다고 관련 순열 비트를 단순 차감하지 않는다. 영향받은 부분의 집합 DP를 재계산하거나 지원 경로 수를 관리한다.

이 집합 정밀화를 구현할 때에도 이전 가방의 성공률을 정확하게 유지하고, 새 중간 가방은 일반 배치 조건을 모든 공급에서 확인한 뒤 **C-와 C+가 집합으로 같아진 경우**에만 정확한 edge로 확장한다. 최종 숫자가 우연히 같은지보다 집합 동등성과 공통 경계가 기준이다.

정밀화 우선순위는 애매한 순열을 많이 구분할 것으로 예상되는 edge, 저렴한 확인, 이전 실패 유형 등으로 정한다. 이 순서는 성능 휴리스틱이며 확률값을 바꾸지 않는다.

### 9.5 성공률 상한에 의한 탈락

일반 배치의 전 공급 조건은 별도로 필수다. 아래 확률식의 P는 첫 가방 제외 옵션에 따른 집계 범위의 이전 정확한 성공률이며, 독립 첫 가방 하한도 별도로 확인한다. 사용자 최소 전체 성공률을 p_min이라고 하자. 다음 가방에 필요한 최소 성공 순열 수는:

    a_min = ceil(5040 * p_min / P)

이다. 아직 미래 가방이 더 있어도 그 가방들의 성공률은 최대 1이므로:

    P * |C+| / 5040 < p_min

이면 즉시 탈락시켜도 안전하다.

예를 들어 P=0.98, p_min=0.95이면 최소 4,886순열이 필요하다. 155개가 확실히 실패하여 상한이 4,885개가 되면 나머지 경로를 검사하지 않아도 된다.

표시는 실수로 해도 되지만 임계값 비교는 정확한 정수·유리수로 수행한다. 시간 초과는 실패 순열로 세지 않는다.

### 9.6 의존성 사전 분석의 역할

의존성은 P7 전체 물리 검증의 대체물이 아니라 **낙관적인 공급 언어를 빨리 만드는 제약**이다.

- 모든 실행에서 필요한 관계만 필수 선행 조건으로 둔다.
- A 또는 B 지지 조건을 논리합으로 유지한다.
- 한 witness의 배치 순서를 필수 의존성으로 복사하지 않는다.
- 직하방에 다른 미노가 있다는 이유만으로 선행이 필수라고 단정하지 않는다.
- 아직 모르는 물리적 막힘을 허용하면 상한으로 쓸 수 있다.
- 증명되지 않은 막힘을 추가하면 안전한 상한이 아니다.

이 구분이 폐기된 사전 분석을 다시 도입할 때 지켜야 할 정확성 경계다.

## 10. 마지막 가방과 비용별 성공률

순열 pi에서 목표에 도달하는 최소 추가 lock 수를 c_pi라고 한다. 불가능이면 무한대다. 중간 가방의 누적 배치 수가 n, 정확한 누적 성공률이 P이면:

    F(n+m) = P * count(pi with c_pi <= m) / 5040
    N_p = min { N : F(N) >= p_min }

비용 순위는 N_p가 우선이다. 같은 값에서는 그 비용 안에 완주하는 정확한 확률 F(N_p)와 이후 보조 기준을 비교한다. 가방 끝까지 더 놓았을 때의 F(n+7)을 별도 보조 지표로 사용할 수는 있지만 이를 N_p에서의 구축률로 표시하지 않는다. UI에서 일반 “배치 수”와 “요청 성공률을 충족하는 비용”이 서로 다른 의미가 되지 않게 한다.

향후 비트셋 DP는 깊이별 최초 accepting 집합을 기록하여 CDF를 계산할 수 있다. 현재는 제한된 홀드 언어에서 실제 공급별 최소 종료 비용을 구한다. 마지막 가방에서는 전체 성공 집합만 같다고 비용까지 확정된 것이 아니다. 필요한 비용 지점의 하한·상한 집합도 일치해야 한다.

비용 N_p만 먼저 인증하려면 더 적은 검사로 충분할 수 있다. 어떤 m에서 P*|C-(m)|/5040 >= p_min이고 P*|C+(m-1)|/5040 < p_min이면 N_p=n+m가 확정된다. 이때 성공률 자체가 아직 구간이면 정확한 단일 수치로 표시하지 않는다. 초기 버전은 확정 결과의 비용별 집합과 확률을 마저 정밀화하여 저장하는 쪽을 기본으로 한다.

목표 40에 도달하면 즉시 성공으로 처리한다. 남은 미노를 놓거나 다음 미노를 spawn할 필요가 없다. see-7은 보이는 미노를 임의 순서로 꺼내는 기능이 아니다. S/Z만으로 끝나는 후보라도 active-first와 제한된 홀드로 도달하는 공급만 성공하며, 목표에 없는 미노를 자유 보류해 S/Z를 꺼내지는 않는다. 이미 보류한 S/Z의 마지막 스핀이 목표를 달성하는 교환은 미사용 현재 미노를 남길 수 있다.

고정 계획에 선택적 잔여 target이 있더라도 끝난 뒤까지 강제로 소비하지 않는다. seed 실행 길이나 선언된 target 개수는 최소 완주 비용의 하한이 아니다.

마지막 가방은 목표 달성 후 후속 가방이 없으므로 성공 순열마다 최종 필드·사용 부분집합이 달라도 된다. 타깃의 기하학은 여전히 사전에 고정되어야 하며, 순열을 본 뒤 새 소모용 배치를 추가하지 않는다.

## 11. 전역 탐색과 안전한 가지치기

### 11.1 가방 경계의 depth-first branch-and-bound

완전한 branch-and-bound의 설계 상태는 정확한 필드, 누적 스핀 수, 구조 계약, 제한된 홀드의 가방 경계, 정확한 누적 확률, 규칙·프로필 식별자를 포함한다. 중간 가방 edge는 7 lock이며 마지막 edge만 부분 비용 CDF를 가진다.

후보 순서는 다음 정보를 이용한다.

- 이전 최선 완주가 사용한 국소 전이.
- 현재 자원으로 만들 수 있는 3~4스핀 전이.
- 다음 구조의 미충족 요구 감소.
- 남은 예산에 필요한 스핀 밀도.
- 성공률 상한과 필수 의존성의 적음.
- 표면·포켓의 유지 비용.

높은 스핀 수만으로 정렬하지 않는다. 4스핀 후 다음 가방이 막히는 후보와 2스핀 후 여러 생산적인 전이가 열리는 후보를 구분한다.

### 11.2 목표 미노 수를 실패 판정으로 만들지 않는 예산 정책

먼저 사용자 상한 안에서 유효 완주를 찾고, 발견한 incumbent의 N_p를 줄인다. 사용자 시작 예산과 목표 미노 수는 여러 비용 contour의 우선순위에 반영할 수 있다. 현재의119개 기본값, 정체 시 예산 확대와 선택적 가지치기는 [집중 탐색](FOCUSED_SEARCH.md)의 구현 설명을 따른다.

좁은 비용 contour에 시간 한도를 두고 더 큰 예산의 작업도 진행한다. 작은 예산에서 해가 없음을 증명할 때까지 더 긴 유효 결과 탐색을 막지 않는다. contour 미완료는 불가능 판정이 아니다.

IDA*식 반복을 도입해도 하한이 기존 질량식에만 머물면 효과가 제한적이다. 구현 명칭보다 하한과 생성 공간의 품질이 우선이다.

### 11.3 안전한 가지치기

| 조건 | 안전하게 버릴 수 있는 이유 |
| --- | --- |
| 충돌·재고 중복·금지 소거·천장 사망 | 명시한 물리·문제 계약 위반 |
| 남은 필수 셀을 재고로 덮을 수 없음 | 포함 관계가 보장된 후보 영역에서의 제약 불만족 |
| 비용 하한이 예산 초과 | 어떤 실제 완주도 예산 안에 못 들어옴 |
| 미래 스핀의 낙관적 상한이 남은 목표 미만 | 완화 모델도 목표에 못 도달함 |
| 누적 성공률 상한이 p_min 미만 | 미래 성공률 1을 가정해도 부족 |
| 고정 계획의 일반 배치 조건 위반 | 단 하나의 모델 공급이라도 홀드 없이 일반 배치 막힘을 피하는 전략이 없으면 허용 확률과 무관한 계약 위반 |
| 같은 완전 상태에서 비용·성공률이 지배됨 | 미래 선택 공간이 동일함 |
| 정확한 가방 합류 불가 | 고정 가방 계획의 공통 경계 계약 위반 |

동일한 상태의 실패 결과를 재사용할 때 비용 한도, 필요한 잔여 성공률, 구조 프로필, 규칙 버전을 함께 비교한다. 해시나 형태 특징만 같다는 이유로 불가능을 옮기지 않는다.

예산 B와 요구 잔여 확률 q에서의 실패는 같은 구조에서 더 작은 예산과 더 높은 요구 확률로만 안전하게 옮길 수 있다. 예산이 늘거나 요구 확률이 낮아진 경우는 다시 판단한다. 저장한 bound의 의미와 단조 방향을 명시한다.

특정 고정 가방 계획의 실패는 그 계획에 한정한다. 경계 상태 자체의 불가능 판정은 허용한 후속 공간을 모두 검사했거나 안전한 bound로 배제했을 때만 저장한다. 생성한 일부 후보의 실패, 시간 제한, 미확정 물리 간선은 경계 전체의 실패 증명이 아니다. 지배하는 label이 미전개 상태라면 작업 목록에 유지한다. 그 label을 폐기하면서 다른 경로까지 지배된 것으로 제거하여 미탐색 상태를 잃지 않는다.

같은 비용 후보에서도 구축률 개선을 탐색한다면 incumbent과 비용이 같다는 이유만으로 전부 잘라서는 안 된다.

### 11.4 선택적 제한

다음은 선택적인 프로필 제한·가지치기 또는 move ordering이며 불가능 증명과 구분한다.

- 포켓 수 제한.
- 작업 영역 폭과 상대 높이 제한.
- 특정 길이 안에 포켓을 소비해야 한다는 제한.
- 늦은 후보의 축소 탐색.
- 낮은 현재 평균 스핀 수.
- 준비 가방 길이 제한.

이 결과를 전체 물리 공간의 실패 인증으로 저장하지 않는다. 전이표에는 ProvenImpossible, ExcludedByProfile, Deferred를 구분한다. 제품 화면에 이 내부 자료를 모두 노출할 필요는 없다.

### 11.5 하한과 용량 상한 강화

현재 미노별 검사는 각 행의 부족 칸을 작은 순서로 합쳐 남은 미노의 재료 4r칸으로 채울 수 있는 행 수를 계산한다. O 이외 남은 종류 수로 한 번 더 제한한 값은 추가 스핀의 낙관적 상한이다. 행 삭제가 기존 행을 합치지 않고 새 빈 행은 10칸이 필요하므로, 실제 가능한 추가 스핀을 과소평가하지 않는다. 이 상한으로 가방 끝 잔여 재료와 이후 최소 비용을 계산하되, 현재 가방에서 목표 도달 가능성이 있으면 대표 7개 타깃 수를 최소 비용으로 오인해 자르지 않는다.

상한을 페이스·순위 기준과 비교하는 것은 별개의 선택적 검사다. 현재 형제 후보의 비교창은 같은 부모 필드에서 같은 다음 미노를 다르게 놓은 후보에만 적용한다. 추적 목표가 같고 최초 배치 가능 집합이 다른 후보를 포함하며, 실제 스핀과 낙관적 가방 말 총 스핀이 모두 낮지 않아야 비교 대상이 된다. 실제 스핀이 더 많은 후보는 원래 구조 점수도 엄격히 높아야 하며, 같은 스핀에서는 원래 점수가 24보다 많이 높을 때만 열세 후보를 줄인다. 무작위 정렬 보정은 이 점수 비교에 넣지 않는다. 첫 가방과 현재 가방에서 목표 달성 가능성이 남은 후보는 보호한다.

각 가방은 `used=0`에서 미사용 종류를 모두 검토한다. 이전 후속 수순은 일치하는 필드·재고의 후보를 먼저 확인하는 힌트로만 쓰고, 고정 접두부로 확정하지 않는다. 같은 사용 마스크의 서로 다른 부모를 위 형제 비교창에 섞지 않는다. 아직 확정하지 않은 스핀 목표의 빈 공간을 다른 후보가 채우면 후보 자체를 자르는 대신 그 목표를 해제하고 결과 필드를 평가한다. 이러한 선택적 비교와 꽉 찬 beam의 진입 생략을 실제 공급 실패나 전역 최적성의 증거로 승격하지 않는다.

이후 더 강한 안전한 하한은 작은 완전 국소 검사부터 도입할 수 있다.

- 다음 스핀 전에 최소 delta개의 무클리어 준비가 필요함을 완전 검사로 증명하면 R+delta가 하한이다.
- 다음 t스핀까지 완화 모델의 최소 lock 수가 d_t이면 d_t+(R-t)가 하한이다.
- 질량·구조·공급 하한은 우선 max로 결합한다. 같은 미노가 여러 요구를 동시에 충족할 수 있으므로 함부로 합하지 않는다.
- 더 긴 단계에는 구조 인터페이스·재고·셀 자원을 상태로 하는 완화 DP/PDB를 사용할 수 있다.

완화 모델은 모든 실제 전이를 포함해야 한다. 블록을 지우면 회전은 쉬워질 수 있지만 필요한 지지나 first-success kick이 사라질 수도 있다. 따라서 “바깥 블록을 제거하고 정확한 스핀 규칙을 적용”한 모델을 자동으로 낙관적인 상한·하한으로 보지 않는다. 필요하면 알려지지 않은 지지를 가상으로 허용한다.

현재 포켓 개수는 미래 스핀 수의 상한이 아니다. 준비 동작으로 새 포켓을 만들 수 있다. 샘플링한 국소 전이 목록만으로 최대 생산량을 계산했다면 그 값은 평가용이며, 완전성을 증명하기 전에는 안전한 pruning에 사용하지 않는다.

## 12. 체스 탐색과의 대응

| 체스 엔진에서 참고할 개념 | Neyra에서의 적용 |
| --- | --- |
| Alpha–Beta의 bound와 조기 중단 | 비용 branch-and-bound, P7 성공률 구간의 임계값 중단 |
| Iterative deepening | 비용·국소 계획 길이별 반복 탐색, 기존 좋은 수순 재사용 |
| Move ordering / principal variation | 생산적인 국소 전이와 기존 완주의 다음 가방을 우선 |
| Transposition table | 정확한 공통 경계의 재사용, 비용·확률별 bound |
| Extension / quiescence | 열린 포켓의 강제 후속을 확인하고 안정 경계에서 평가 |
| History | 제약 실패 유형·성공 전이의 우선순위 |
| MCTS/PUCT | 필요 시 나중의 후보 순서·다양성 보조 기능 |

null move로 미노를 건너뛰거나, 무클리어 수라는 이유만으로 안전하게 버리는 가정을 사용하지 않는다.

Stockfish의 공식 용어와 Lc0의 policy/value 기반 MCTS 설명은 탐색 제어를 비교하는 참고 자료다. 체스 엔진의 성능을 Neyra의 예상 속도로 옮겨 주장하지 않는다. 특히 “MCTS는 10가방 이상을 원천적으로 못 찾는다”는 일반 정리를 주장하지 않는다. 현재 구현의 표현·후보 생성·평가가 부적절하다는 진단이 근거 있는 결론이다.

### 12.1 테트리스 봇 소스에서 추가로 반영하는 원리

[Cold Clear·CC2·공개 fusion 감사](research/COLD_CLEAR_FUSION_AUDIT.md)를 추가했다. MochBot 제작자 공개 설명은 본체가 비공개이고 클라이언트 일부만 공개라고 밝히므로, fusion 코칭 엔진의 알고리즘을 MochBot 본체의 것으로 단정하지 않는다. 협업 저장소의 Pensilbot도 별도로 확인했으며 비공개 소스 사본은 이 공개 저장소에 포함하지 않는다.

이번 검토로 주 제어기를 다시 바꾸지는 않는다. 가방 경계 branch-and-bound와 정확한 P7를 유지하고, 다음 내부 구조를 보강한다.

- **후보 내부 실행 DAG 우선:** 고정 계획 하나의 P7 실행 그래프에서 동일 실행 상태를 합친다. 서로 다른 가방 경계나 worker를 하나의 전역 DAG로 묶는 것은 기본값이 아니다. 재사용할 때도 물리 상태와 경로별 비용·확률·witness label을 분리하고, 최소 비용과 최대 확률을 다른 후보에서 가져와 섞지 않는다.
- **재개 가능한 frontier:** 후보 생성 cursor, 물리 witness, P7 결과를 폭 확대·비용 contour 변경·pause/resume 사이에 유지한다. root부터 계산을 반복하지 않는다.
- **공유의 비용 제한:** 기존 worker 내부 캐시를 우선 사용한다. 추가 캐시나 진행 중 질의 합치기는 실제 중복률, 조회·복사·할당 비용, 보관 메모리까지 확인한 뒤 선택한다. worker 사이의 work stealing이나 잠금이 필요한 전역 캐시를 전제하지 않는다.
- **점진적 후보 할당:** 이번 작업에서 상위 후보 일부를 확인하되 나머지는 Deferred로 남긴다. 낮은 순위나 점수 차이는 불가능 증명이 아니다.
- **포켓 소비 후 평가:** 스핀을 실제로 얻은 보상과 미래 구조의 추정 가치를 분리한다. TSD/TST 가상 처리나 공격량 평가를 가져오지 않고, 모든 관련 미노의 Spin Single과 후속 구조로 다시 정의한다.
- **충돌 anchor mask:** 같은 보드에서 충분히 많은 질의를 할 때만 사전 계산한다. 질의 몇 개를 위해 전체 mask를 생성하면 손해일 수 있다. 물리 충돌과 24행 사망 판정은 별도 조건으로 유지한다.
- **마감 의무에 따른 extension:** 현재 포켓의 소비와 공통 경계 확인을 위해서만 제한적으로 더 본다. 과거에 스핀했다는 사실만으로 계속 확장하지 않는다.
- **완료 결과의 원자적 반영:** activePreview는 작업 중에도 갱신하지만 인증 incumbent은 완결된 결과로만 바꾼다. runId/config fingerprint가 다른 늦은 worker 결과는 폐기한다.

스케줄러는 GenerateGoals, RefineP7, DescendBoundary의 작은 작업을 번갈아 진행한다. 생성 시도 수, 새 고유 상태 수, 중복 작업량, 물리 질의 수, P7 정밀화 비용을 따로 계측한다. 캐시 hit가 높다는 이유로 반복 생성 비용을 숨기지 않는다.

Live bot의 미지 next 기대값·생존 fallback·평균 평가를 구축률로 사용하지 않는다. 단일 ply와 가방 하나의 탐색 깊이도 구분한다. 이러한 원리를 가져왔다는 사실만으로 10가방 이상 완주 성능을 검증한 것은 아니다.

### 12.2 정적 보드 평가

평가는 명시적인 정수·bitset 특징과 구조 계약으로 구성한다. NNUE, 학습용 데이터, 신경망 추론을 요구하지 않는다. [Cold Clear의 정적 평가](https://github.com/MinusKelvin/cold-clear/blob/279edd7c3177ff8077f6a930193397814b281f27/bot/src/evaluation/standard.rs)에서 높이·거친 표면·묻힌 빈칸·overhang·T 슬롯을 분리하는 원리를 가져오되, 대전의 공격량·TSD/TST·콤보·PC 보상을 복사하지 않는다. 공개 fusion에는 NN 평가 경로도 있으므로 전체 평가기를 도입하지 않는다.

#### 최초 평가 감사와 현재 반영

최초 검토본은 overhangs와 near_rows에 단순 보상을 주어 실제 스핀으로 소비하지 못할 구멍을 높게 평가할 수 있었다. 현재는 구체적 목표와 실제 스핀 witness를 구분하며, 구멍의 기본 비용 2.0에 해결되지 않은 구멍당 0.5를 더한다. 실제 witness의 required_empty와 겹치는 구멍만 추가 비용을 면제하고, 준비 목표를 선언한 것만으로 면제하지 않는다. 상세한 표면·접근성·지붕 평가는 [구조 평가](STRUCTURAL_EVALUATION.md)를 따른다.

또한 열 높이 합에는 블록 수와 holes가 함께 포함된다. B를 실제 잔여 블록 수, H를 열의 최고 블록 아래에 있는 빈칸 수라 하면 다음 항등식이 성립한다.

    sum(column_height) = B + H
    B = 4 × placed_pieces − 10 × completed_singles

같은 배치 수·싱글 수의 후보끼리 비교할 때 B는 상수다. 따라서 aggregate height와 holes를 별개의 독립 특징처럼 두면 같은 결함을 중복 가중한다. 최대 높이와 스폰 위험은 별도의 유용한 정보이므로 유지한다.

#### 계산할 특징

| 특징 | 정의와 용도 | 계산 경계 |
| --- | --- | --- |
| 비용 하한 | 현재 lock 수 + 남은 과제의 증명된 최소 추가 lock 수 | 전역 목표의 우선 기준. 추정 포켓 점수를 안전한 하한에 더하지 않는다. |
| 즉시 스핀 | 이미 정확한 물리 witness가 있고 재고가 허용하는 Spin Single | 사용 가능한 미노 수와 충돌하는 포켓을 함께 고려한다. 같은 공간의 여러 회전을 중복 보상하지 않는다. |
| 구조 포켓 | 목표 mask·지지·빈 공간·kick 순서 조건이 있는 미완성 슬롯 | 단순 overhang 수를 대체한다. 구조적 후보와 검증 완료 슬롯을 구분한다. |
| 미완료 의무 | 포켓을 유지·소비하기 위해 필요한 미노, 누락 셀, 유지해야 할 빈 공간 | 완료 기한과 남은 재고를 함께 저장한다. 이름만 붙인 구멍에는 예외를 주지 않는다. |
| 불필요한 holes | 현재 활성 구조 계약에 속하지 않는 묻힌 빈칸 | 강한 음의 정렬 특징. 구멍이라는 사실만으로 불가능 판정을 내리지 않는다. |
| 덮임 깊이 | 불필요한 빈칸 위에 쌓인 블록 수와 영향을 받는 행 | 얕은 수리와 깊이 묻힌 결함을 구분한다. |
| 양측 표면 | 활성 스핀 영역을 제외한 좌·우 적재 영역의 높이 차이와 좁은 틈 | 중앙의 의도된 통로까지 전체 bumpiness로 벌하지 않는다. 통로 위치는 고정하지 않는다. |
| 상단 위험 | 실제 최대 높이, 현재 스폰 충돌, 예정 경로의 상단 여유 | 24행 사망과 관련된 정보. 단순 평균 높이보다 직접적이다. |
| 배치 의존성 | 강제 선행 관계, 동시에 만족해야 할 지지 조건, 홀드로 해결하지 못할 충돌 | 정렬용 추정과 정확한 P7 결과를 분리한다. OR 경로가 있는 관계를 단일 DAG로 단정하지 않는다. |

현재 행별 점유 수, 열 높이, holes와 덮임 깊이는 실제 점유 높이까지만 순회해 계산한다. 물리적 24행 천장과 접근 영역의 범위는 유지한다. 구조 슬롯 검사는 기존 목표 생성기의 작은 활성 영역과 미노별 mask를 재사용한다. 평가 때문에 전체 보드의 정확한 도달성을 다시 생성하지 않는다. 같은 결과 필드의 중복 후보를 먼저 줄일 수 있다면 평가 캐시를 추가하기 전에 그 중복을 없앤다.

#### 정렬과 가지치기 분리

다음 항목은 v2 평가 설계의 책임 구분이며 현재 코드의 사전식 비교 순서를 뜻하지 않는다. 현재 같은 깊이의 순위는 실제 스핀에 유계 필드 보정을 한 번 더하며, 1스핀 차이만 뒤집을 수 있다. 완주는 최소 비용·확률, 공개 중간 경로는 첫 가방을 포함한 효율로 별도 비교한다.

1. 정확한 합법성·현재 예산·성공률 상한을 통과하는가.
2. 비용 하한이 작은가. 완주 후보는 실제 N_p를 먼저 비교한다.
3. 현재 구조 의무를 충족하고 사용할 수 있는 스핀을 만드는가.
4. 불필요한 구멍과 덮임 깊이·기한이 지난 의무가 적은가.
5. 양측 적재 표면과 스폰 여유가 좋은가.
6. 앞 조건이 같을 때 입력 비용과 탐색 다양성을 사용한다.

목표가 준비인 첫 가방과 스핀을 소비하는 후속 가방은 같은 보상을 기계적으로 적용하지 않는다. 첫 가방의 0스핀은 우선 검토할 준비 경로이며 강제 조건이 아니다. 이후에도 4스핀 같은 고정 할당량을 강제하지 않고, 남은 스핀·lock 예산과 잔여 블록 자원으로 필요한 생산성을 평가한다.

구조 포켓의 수를 더할 때 서로 겹치는 occupied/empty 요구나 동일 미노 재고를 중복 사용하지 않는다. 일곱 종류의 작은 재고 문제로 호환되는 조합을 고르거나, 정확한 조합 계산을 하지 않았다면 그 수치를 휴리스틱으로만 사용한다. 정적 점수를 성공률로 변환하지 않으며 구축률은 P7 검증이 담당한다.

표면 점수가 낮거나 hole이 많다는 이유만으로 ProvenImpossible을 기록하지 않는다. 평가에 따라 우선순위를 뒤로 미룬 후보는 Deferred이며, 엄밀한 가지치기는 별도의 증명된 bound에서만 수행한다.

## 14. GUI 계약과 최초 자산 통합 계획

### 14.1 상태 분리

    activePreview : 지금 처리하는 실제 노드의 작은 snapshot
    bestPartial   : 지금까지 좋은 미완성 후보
    incumbent     : 설정 성공률을 충족한 40스핀 완주
    inspection    : 사용자가 보고 있는 후보와 프레임

현재 기본 화면은 최신 보관 경로다. 사용자가 탐색 중 화면을 선택했을 때만 해당 worker의 현재 후보를 관찰한다. 최신 경로·탐색 중 화면·기록 재생을 구분하고, 일시정지·재개와 같은 후보의 새 기록 갱신이 선택한 화면에 반영되어야 한다. 위 상태 이름은 설계상의 역할이며 실제 프로토콜 필드명 전체를 뜻하지 않는다.

미노별 재생은 문서 내보내기와 같은 Clearra 팔레트와 `placedCells` 복원을 사용한다. 필요한 프레임까지만 지연 복원하고 같은 기록의 이전 프레임은 재사용한다. 배치가 닿는 행만 복사한 뒤 실제 줄 삭제를 적용하여 기존 블록의 색상과 과거 프레임을 보존한다. 새 경로를 받으면 캐시를 비우며, 물리 좌표가 없는 구버전 기록의 미확인 색상은 회색으로 남긴다. 열 번호나 가방 완료 장식을 되살리지 않는다.

### 14.2 깜빡임 제거

최초 검토본은 미검증이면서 checked>0일 때만 설명 문단을 mount해 생성·검증 전환마다 높이가 달라졌다. 유지할 계약은 후보 상태를 고정 높이의 한 줄로 표시하는 것이다.

후보의 candidateId는 유지하고 revision만 증가시킨다. 인증 상태는 다음처럼 명시한다.

    Unchecked
    Checking
    Certified
    Rejected
    BudgetExhausted

화면의 전체 상태는 “탐색 중”으로 안정적으로 유지한다. 상세 한 줄에서 현재 가방 검증 수나 정확한 구축률을 갱신한다. 전체 탐색에는 끝을 알 수 없는 임의 완료율을 표시하지 않는다. 분모가 확정된 검증 작업에만 진행률을 사용한다.

공유 P7 검증의 진행 수는 실제로 개별 BFS를 실행한 순열 수가 아니다. |C-| + (5040-|C+|)처럼 성공 또는 실패가 확정된 순열 수를 “판정 확정”으로 표시할 수 있다. 후보가 바뀌어도 상태 행의 높이는 유지한다.

보드 갱신은 몇 Hz로 합치고 숫자는 tabular figures를 사용한다. 전체 수순 데이터는 선택·내보내기 때 가져온다.

### 14.3 Clearra에서 가져올 실제 소스

최초 검토에서는 자체 BoardPreview·ProgressStrip와 dark CSS만으로 자산 재사용을 완료할 수 없다고 판단하고 아래 통합을 계획했다. 이 표는 그때의 통합 대상이며 현재 사용 파일의 전체 목록이 아니다. 실제 출처·수정 기록과 라이선스는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)를 따른다.

| Clearra 소스 | Neyra 용도 |
| --- | --- |
| WorkspaceShell.svelte | 필드와 제어 영역, 반응형 shell |
| WorkspaceControlPanel.svelte | 설정 입력·실행 제어 |
| SolutionBoardPreview.svelte | board·미노 표시 |
| WorkspaceProgressStatus.svelte | 상태 행과 확정 작업의 진행 표시 |

원본 위치는 packages/clearra-ui/src/lib/workspace 및 player 계열이다. 전체 Tauri/다중 도구 navigation을 가져오지 않는다. 단일 탐색 도구의 좁은 화면에 필요한 컴포넌트만 사용한다.

원본 경로·커밋·hash·수정 내역을 manifest에 남기고 MIT 고지를 보존한다. “색상 참고”가 아니라 실제 파일과 adapter import가 검토 가능해야 한다.

## 15. 단계별 수용 기준 — 완료 목록이 아님

### 단계 A: 규칙과 재생 기준

아래는 물리 계약을 변경할 때 확인할 범위다. 이미 완료한 SRS+ 원문 대조를 무관한 변경마다 반복하는 배포 조건으로 사용하지 않는다.

- 공식 fixture의 84개 회전 전이와 순서 있는 offset 대조.
- 공식 O 원위치 회전 자료 보존, O 스핀 제외, 점유 셀 등가 탐색 간선의 축약 검증.
- 셀 기준 천장·first-success 사망·가짜 ceiling spin 방지.
- 회전별 padding 원점 사례.
- strict24 기준 reference forward와 reverse target 동치 검사.

### 단계 B: 구조 생성기

- 첫 가방의 무제한 전체 도달 위치 나열 제거.
- 국소 스핀 목표, phase별 요구, 제한된 side packing.
- 첫 가방 0스핀 분기와 소거 포함 분기 구분.
- 알려진 유효 국소 전이를 입력으로 주지 않고 재발견하는 fixture.
- 작은 문제에서 완전 기준 탐색과 비교하여 안전한 컷의 누락 검사.

### 단계 C: P7 공유·지연 인증

- 현재 제한된 홀드의 순열별 평가기를 reference로 보존.
- 일반 배치 전 공급 보장, clear 보류, 강제 막힘, 첫 빈 가방 대칭, 여러 삭제 이력, spawn 차단과 마지막 held 배치의 계약을 보존.
- 비트셋 DP를 구현하면 5,040개 reference의 성공 집합·일반 배치 보장 집합·최소 비용이 모두 일치.
- 실패 edge에 대체 경로가 있을 때 upper가 잘못 감소하지 않음.
- 시간·노드 한도는 Unknown.
- 마지막 가방 CDF 및 목표 달성 후 미사용 spawn 생략.

### 단계 D: 전역 DFS와 bound

- exact state TT, prefix 확률, budget contour, incumbent.
- 구조 프로필 제외와 불가능 증명 분리.
- 119개 희망 목표를 넘는 사용자 상한 내 유효 결과도 채택.
- 비용이 같을 때 성공률 개선 보존.
- 검증되지 않은 용량 추정은 정렬에만 사용.

### 단계 E: GUI

- 실제 Clearra 컴포넌트와 원본 manifest.
- 최신 경로를 기본 화면으로 유지하고 미노별 기록 갱신 반영.
- pause → 탐색 중 화면 → resume에서 선택한 worker의 관찰 재개.
- 같은 id의 새 revision 반영.
- 생성/검증 반복에도 패널 높이 불변.
- 모바일·데스크톱에서 과도한 세로 설명과 내부 조건 노출 없음.

### 단계 F: 실제 탐색 품질

같은 브라우저·시간·메모리·seed 집합에서 이전 엔진과 비교한다. 다음을 함께 기록한다.

- 처음 찾은 설정 성공률 이상의 40스핀 완주까지 시간.
- 그 결과의 N_p와 정확한 전체 구축률.
- 같은 시간의 최선 비용과 부분 후보의 (배치 수, 스핀 수, 구축률).
- 생산적인 2가방 경계 수와 이후 10가방 이상으로 이어진 수.
- 목표 하나당 기하학 후보 수, 역도달성 호출 수, P7 시간.
- 안전한 가지치기·프로필 제외·미확정 수.
- peak memory 및 UI 응답성.

단순히 10가방에 도달했거나 수백만 노드를 처리했다는 이유로 성공 판정하지 않는다. 새 빈 필드 탐색에서 유효한 긴 완주를 실제로 찾아야 한다. 119개 희망 목표 또는 더 짧은 112개 달성은 품질 개선 목표이며 출시 합격의 유일한 조건이 아니다.

## 16. 보류하는 확장

- 낮은 구축률 후보의 고정 종료 모양을 다시 타일링하는 전용 지연 탐색. 현재 생성 중 자연스럽게 얻는 대안의 별도 보존과 구분한다.
- 변형별 성공 순열 집합의 합집합. 확률의 단순 합 금지.
- 가방별 재시작 비용과 초기 실패 우선 가중치.
- 검증된 구조 추상화의 큰 PDB.
- 후보 순서 학습·MCTS 보조 scheduler.
- 더 넓은 구조 프로필.

교차 타일링을 켜더라도 서로 다른 variant의 중간 edge를 섞어 가상의 실행을 만들지 않는다. 각 variant는 자체 실행 그래프를 가지며 공통 종료 필드·진행도·공급 경계를 인증한 뒤 성공 집합을 합친다.
