# GA 학습과 실제 배치 검증

현재 학습 경로는 작은 배치 평가 계수 벡터를 진화시키는 유전 알고리즘(GA)이다. 목표는 빈 필드에서 고정 가방 계획으로 **40번의 스핀 싱글을 완성**하는 것이다. 우선 상한 안의 완주를 찾고, 이후 사용 미노 수를 줄인다. 기본 선호 목표 119미노와 허용 상한 126미노를 구분한다.

공개 GitHub Pages는 기존 구조 평가기 또는 사용자가 명시적으로 선택한 로컬 GA 계수로 다중 경로를 탐색한다. 모델 선택은 새 탐색에만 적용하며 파일은 브라우저 메모리에 둔다. 관측 수집, 비공개 자료 전송, CNN 전송, Supabase 연결은 종료했다. GA 실행과 체크포인트는 기존 소유자 전용 비공개 작업실에 둔다. 이전 CNN 문서는 Git 이력과 오프라인 호환 코드의 설명이며 현재 서비스의 학습 계약이 아니다.

현재 새 실행은 `neyra-ga-config-v3` / `neyra-ga-sonic-physical-v4`다. **학습 중의 공급 확률·quiet-safe 전수 점수를 완전히 제외하고 실제 물리 40L 후보 생성을 먼저 최적화한다.** 기존 config-v1 / policy-v2와 config-v2 / policy-v3는 원래 선택·난수·공급 의미를 유지해 재개한다. 원본 정책을 바꾸려면 명시적으로 새 실행을 만든다.

아래의 **현재 v4 학습** 절이 새 실행에 우선한다. 이후 v2/v3의 공급 인증·프런티어 설명은 기존 실행을 읽고 이어가기 위한 계약이다. 공개 탐색의 공급 인증은 여전히 유지한다.

## 현재 v4 학습: 완주 후보를 먼저 만들기

### 확률을 제외하는 범위

GA가 미노를 선택할 때는 canonical Sonic Drop `reachable_locks`의 모든 후보를 점수화한다. 실제 입력 재생, 충돌, 24행 경계, 가방별 종류 중복 금지, O 스핀 제외와 0줄 또는 정확히 1줄 스핀 싱글 조건은 그대로 적용한다. 각 가방의 미노는 하나씩 배치하며, 완전한 가방에는 일곱 종류를 한 번씩 사용한다.

v4 rollout은 P7 검증기를 만들지 않는다. 성공 공급 수, quiet-safe 수, 첫 가방 확률, 확률 곱이 적합도나 부모 선택에 들어가지 않는다. 원래 필드가 호환성 때문에 남아 있어도 확률을 실제 측정한 것으로 해석하면 안 된다. 화면과 물리 아카이브에는 **공급 확률 미측정**으로 표시한다. 공급 검증 호출 수가 0인지 별도로 확인할 수 있다.

이 단계에서 얻는 것은 실제 입력으로 재생할 수 있는 **고정 typed 계획의 대표 경로**다. 임의의 공급 순서를 같은 배치로 해결하는 경로라는 뜻은 아니다. 공급 순서에 따른 clear-only hold와 모든 공급의 quiet-safe 조건은 다음 탐색·수리 단계에서 정확히 검사한다. 물리 경로를 확률 인증 없이 공개 탐색의 검증된 경로에 넣지 않는다.

### 적합도와 정체 대응

같은 개체의 빈 필드 평가에서 40스핀 완주 횟수를 먼저, 실제 스핀 합계와 최소 스핀을 다음으로 비교한다. 완주 비용·최종 높이는 동률을 정리한다. 최고 한 번의 기록뿐 아니라 평균과 최소값을 함께 표시한다. 동일 개체의 평가 재사용 횟수는 새로 수행한 에피소드 횟수와 분리한다.

부모의 유용한 계수 조합을 보존하기 위해 대부분의 후손은 선택한 부모에서 변이하고 일부만 교차한다. 작은 변이·보통 변이·넓은 변이를 섞고, 여러 세대의 정체가 이어지면 새 개체 비율과 넓은 변이를 늘린다. GA의 변이 폭을 높이는 것은 신경망의 학습률을 높이는 것과 다르며, 기존 경로를 파괴할 수도 있다.

24개 계수와 256개 문맥 계수를 명시적으로 선택한다. 기본값은 24개다. 256개 정책은 남은 가방 종류·배치 종류·가방 진행·남은 비용·착지 주변 모양의 상호작용을 표현한다. 처음 확대할 때 추가 계수는 0으로 두고, 변이 때는 차원 증가에 맞춰 좌표 수와 추가 계수의 변이 폭을 제한한다. 자세한 구조는 [GA_POLICY.md](GA_POLICY.md)에 있다. 두 정책 중 더 큰 쪽이 항상 낫다는 가정은 하지 않는다.

### 실제 경로로 돌아가서 이어가기

유망한 완전 가방 접두 경로를 제한된 아카이브에 저장하고, 일정한 빈도로 그 입력을 실제 재생한 뒤 새로운 후속 배치를 탐색한다. 깊이가 다른 접두 경로를 남겨 이미 늦게 막힌 경로만 반복하지 않도록 한다. 남은 잠금에서 O를 제외한 모든 미노가 한 줄씩 지운다는 낙관적 상한으로도 40에 도달할 수 없는 접두는 복귀 대상에서 제외한다. 이 조건은 물리적 필요조건이며 확률 검사가 아니다.

복귀 상태를 공유할 때에도 선택된 전체 입력 경로를 보관한다. 같은 물리 보드·스핀·비용의 복귀 상태를 한 칸으로 취급하는 것은 물리적 후속 탐색의 재사용이다. 서로 다른 고정 계획의 공급 성공 집합을 합치거나 공급 증명을 재사용하지 않는다.

30스핀 이상이며 남은 배치가 14개 이하인 완전 가방 접두에는 작은 후반부 beam 탐색을 적용할 수 있다. 한 수의 모든 canonical 도달 배치를 열거한 뒤, 실제 스핀과 학습한 평가로 다음 층의 후보를 고른다. 기본 폭은 64개이며 다음 층의 중간 보관량은 그 8배, 한 번의 시도는 최대 20,000회 물리 도달 질의로 제한한다. 한 작업 단위마다 한 종류의 미노를 조사하고 층·미노·후보 위치를 저장하므로 일시정지 후 같은 지점에서 이어간다.

한 세대에 최대 한 번 후반부 탐색을 시작하고 같은 보관 접두에 같은 설정의 결정적 탐색을 반복하지 않는다. 물리 접두·계수·폭·배치 상한·질의 예산을 묶은 시도 기록을 최대 4,096개 유지한다. 이 기록은 전체 이력의 영구 중복 제거가 아니며, 명시적으로 새 실행을 만들면 새로 시도할 수 있다. 용량이나 질의 상한으로 끝난 결과는 불가능성 증명이 아니다. 찾은 전체 경로는 빈 필드부터 입력을 재생해 확인한다. 이 과정은 전체 배치를 선택적으로 남기는 제한된 탐색이며, GA의 한 수 합법 배치 열거와 구분한다.

화면과 저장 자료에서 다음을 분리한다.

| 지표 | 의미 |
| --- | --- |
| 빈 필드부터의 평가 | 현재 개체의 정책으로 처음부터 새로 계산한 결과 |
| 보관 경로 이어가기 | 저장된 입력 접두를 재생한 후 새로 탐색한 suffix의 전체 결과 |
| 후반 경로 탐색 | 유망한 접두의 마지막 한두 가방을 여러 후보로 탐색한 결과; 별도의 시도·완료·40L 횟수 |
| 계승한 경로 | 이전 실행에서 실제 재생을 검증해 가져온 기록 |
| 보관 중인 서로 다른 40L 후보 | 최대 32개의 고정 typed 계획; 같은 미노별 목표를 다른 순서로 실행한 경로는 한 개 |
| 확률 인증 완료 | 별도 exact 공급 검증을 통과한 결과; v4 학습 지표에는 없음 |

후속 경로의 가중치를 다시 부모 후보로 사용할 수 있지만, 그 가중치가 빈 필드부터 같은 경로를 재현한다고 가정하지 않는다. 새로 빈 필드 평가를 거친 결과만 그 개체의 적합도로 사용한다. 저장된 접두를 재생한 것만으로 새로운 완주 성공률을 올리지 않는다.

### 원본을 보존하는 계승과 재개

v4 `fork`는 원 실행의 **물리 최고 아카이브 가중치와 실제 입력 경로**를 우선 계승한다. 원 실행에 해당 아카이브가 없으면 기존 선택 가중치로 시작하며, 없는 과거 경로를 복원했다고 표시하지 않는다. 새 실행에서는 세대·난수·평가 점수를 새로 시작하고, 계승한 경로를 실제 재생한 뒤 출처를 남긴다.

정확한 `resume`은 원 설정 그대로 계산을 이어간다. 물리 rollout 중간, 후보 열거 위치, 진행 중인 접두 복귀 탐색도 체크포인트에 저장한다. 가져온 경로의 입력·프레임·가방 재고와 가짜 공급 인증 필드는 다시 검사한다. 체크포인트의 누적 optimizer 통계는 소유자가 제공한 실행 기록이며, hash만으로 성능을 인증하지 않는다.

```json
{
  "schemaVersion": "neyra-ga-config-v3",
  "populationSize": 32,
  "generations": 64,
  "seed": 20261121,
  "episodesPerGenome": 4,
  "maxPieces": 126,
  "pieceGoal": 119,
  "physical": {
    "contextFeatures": false,
    "actionNoise": 0.025,
    "continuationEvery": 2,
    "archiveCapacity": 96,
    "repairBeamWidth": 64
  }
}
```

`contextFeatures:true`는 256개 계수를 사용한다. `continuationEvery:0`은 정책으로 접두에서 이어가기를 끄고, `repairBeamWidth:0`은 별도의 후반부 beam 탐색을 끈다. 이전 물리 초안 설정에 `repairBeamWidth`가 없으면 재개 의미를 보존하기 위해 비활성으로 해석한다. 행동 노이즈는 실제 합법 후보의 점수 순서만 바꾸며 합법성 조건을 바꾸지 않는다. 큰 세대 수나 반복 횟수를 설정하는 것만으로 학습 효율이 좋아지는 것은 아니다.

```sh
neyra-ga fork --resume OLD_CHECKPOINT --config PHYSICAL_CONFIG \
  --checkpoint NEW_CHECKPOINT --output INITIAL_SNAPSHOT
neyra-ga train --resume NEW_CHECKPOINT --seconds 120 \
  --output MODEL --checkpoint NEW_CHECKPOINT --report TRAINING_REPORT
neyra-ga evaluate --model MODEL --seed-start 53000001 --episodes 64 \
  --output FROZEN_REPORT
```

계승한 경로와 빈 필드 정책의 실력은 서로 다르므로, 완주 안정성은 학습에 쓰지 않은 시드에서 가중치를 고정한 실제 평가로 확인한다. 시드는 같은 문제의 탐색 결정을 바꾸며 랜덤 공급 분포의 독립 게임을 뜻하지 않는다. 원시 40L 후보 한두 개, 세대 종료, 평균 개선만으로 안정적 완주나 학습 완료를 선언하지 않는다.

실제 완주 경로를 확보한 뒤에는 각 관측 상태의 모든 합법 대안과 선택 수의 상대 점수로 작은 정책을 별도 학습시킬 수 있다. 이렇게 경로를 정책으로 압축한 실험은 GA 단독 결과와 분리하고, 원본 경로·최적화 방법·고정 정책 재평가를 함께 남긴다. 같은 한 경로를 여러 시드로 재현한 횟수와 새로운 고정 배치 수를 혼동하지 않는다. 온라인 GA에 외부 선형계획 풀이기가 포함되어 있다는 뜻도 아니다.

### 후속 확률 학습으로 연결

다음 순서는 물리 완주 후보 생성 → exact 확률 탐색과 반례 수리 → 확률을 고려한 재학습이다. 2단계에서는 낮은 확률 후보를 모두 버리는 대신, 실패 공급·첫 막힘 위치·수리 비용을 모으고 높은 확률 경로와 많은 스핀 경로를 각각 보존한다. 새 신경망의 값은 여전히 검증 순서·탐색 예산의 힌트다.

물리 후보가 고정 계획으로 거의 구축되지 않는다면 그 후보를 그대로 확률 모델의 성공 표지로 사용할 수 없다. 필요하면 접두를 바꿔 다시 생성해야 한다. 이후 정책을 fine-tuning할지 별도 확률 정책으로 분리할지는 물리 완주 후보의 다양성·공급 검증 통과율·수리 가능성을 측정해 결정한다. 이 문서의 방향이 해당 후속 학습까지 구현되었다는 뜻은 아니다.

## 이전 v2/v3 계약과 비교 기준

## 왜 작은 GA로 시작하는가

처음부터 정답 보드·완주 경로·신경망 표지를 모으지 않아도 실제 실행 성과로 계수를 비교할 수 있다. 작은 계수 벡터는 CPU에서 평가하기 쉽고 모델·데이터 전송 운영을 줄인다. 다만 유전 알고리즘도 개체마다 배치와 공급 검증을 실행해야 한다. 자료가 필요 없다는 사실이 계산이 적게 든다는 보장은 아니다.

Tetris의 평가 함수 계수를 최적화한 기존 연구는 이 접근의 근거다. 특히 Thiery와 Scherrer의 연구는 특징 선택과 최적화 방법의 중요성을 보여 준다. 이 연구의 cross-entropy 방법은 GA와 다른 알고리즘이며, 일반 Tetris의 성과를 Neyra의 Sonic Drop·스핀 싱글·제한된 홀드 조건에 그대로 옮길 수는 없다. Deep Neuroevolution 연구 또한 GA의 가능성을 보여 주지만, 해당 계산량과 성능은 Neyra의 비용 추정치가 아니다.

## 개체와 배치 환경

개체는 원시 필드·배치 특징에 곱하는 유한한 실수 계수들이다. 초기 계수는 명시적으로 **미학습 초기값**이다. 수동 특징과 초기값은 유도 편향이며, 기존 탐색 결과를 정답으로 모사한 학습 표지가 아니다.

각 배치 단계에서 현재 가방에 남은 모든 미노의 canonical `reachable_locks` 결과를 조사한다. 실제 입력으로 도달한 Sonic Drop 잠금만 허용한다. 충돌, 24행 경계, SRS+, O 스핀 제외, 0줄 일반 배치 또는 정확히 1줄 스핀 싱글이라는 규칙을 유지한다. 기존 공개 탐색의 beam·페이스·형제 후보 비교·구조 예측·futility 가지치기는 GA 후보 생성에 사용하지 않는다.

정책은 열거한 합법 배치의 점수로 다음 수를 선택한다. **가능한 한 수를 모두 평가하는 것과 가능한 전체 수순을 완전 탐색하는 것은 다르다.** 작은 GA가 최적 수순을 보장하거나 비선택적 전수 탐색을 구현했다고 표현하지 않는다.

유전 연산은 다목적 비지배 순위와 분산도, 보존 개체·아카이브 부모, 계수 교차와 변이로 구성한다. 정체 시 변이와 무작위 유입을 늘린다. 확률·스핀·비용 프런티어 최대 32개, 서로 다른 typed 첫 가방 기반 최대 16개를 별도로 보존하므로 현재 점수가 낮다는 이유만으로 모든 기반을 같은 선택에 종속시키지 않는다. 무작위 상태, 세대, 개체와 반복 실행 위치를 저장하므로 중단과 재개를 같은 계산으로 이어갈 수 있다.

원시 최대, 엄격한 100% 접두 경로, 양의 확률 경로의 기록과 실제 리플레이를 분리한다. 서로 다른 계수가 같은 행동을 낳는 경우도 행동 식별자로 계수한다. 동일 개체 평가 재사용과 행동 중복은 다른 지표이며, 행동 식별만으로 계산 전에 모든 중복 실행을 제거했다고 표현하지 않는다. 현재 best의 원시 스핀이 감소해도 역대 원시 최대와 증거는 유지한다. 이전 v2 기록에서 숫자만 남고 수순이 사라진 과거 최대를 재구성하지 않는다.

현재 `neyra-ga-features-v1`은 24개 계수를 사용한다. 실제 스핀, 최대·합계 높이와 셀 수, 묻힌 빈칸·깊이, 표면 차이와 우물, 행·열 전이, 행의 남은 셀 수, 덮인 빈 공간과 세 모서리 공간, 배치 높이와 접촉, 미노 종류, 막힌 스폰을 정규화해 평가한다. 이러한 기하 특징은 준비 형태를 구분하는 수단이며 실제 스핀이나 공급 성공의 증거는 아니다.

## 원시 성과와 인증 성과

| 기록 | 의미 | 의미하지 않는 것 |
|---|---|---|
| 원시 스핀 | 실제 배치 경로에서 일어난 스핀 싱글 | 모든 공급에서 그 계획을 만들 수 있음 |
| 인증 접두 경로 | 첫 가방부터 연속해서 공급 계약을 통과한 경로 | 이후 원시 경로도 인증됨 |
| 확률 완주 | 목표 스핀과 quiet-safe·양의 구축률 및 비용 조건을 통과한 종료 경로 | 100% 완주 또는 전역 최적 미노 수 |
| 엄격한 100% | 첫 가방부터 각 공급과 종료 비용 CDF가 모두 5,040/5,040인 접두·완주 경로 | 모든 보드에서의 완주 능력 |
| 세대 완료 | 설정한 개체 평가와 유전 연산 완료 | 학습 목표 달성 |

한 가방은 미노 종류별 고정 logical target과 삭제 이력을 가진 계획으로 만든다. 그 다음 기존 `VerificationJob`의 실제 입력 검사와 5,040개 공급 모델을 사용한다. 모든 공급의 quiet-safe 조건, clear-only hold, 비어 있는 가방별 홀드 시작, 첫 가방 반사 모델과 마지막 부분 가방의 비용 CDF를 적용한다. 새 v3는 각 가방 성공 공급 수의 곱을 첫 가방부터 계산한다. 종료 비용은 그 미노 수까지의 CDF와 짝지으며, 더 큰 비용에서의 전체 성공률을 싼 비용 옆에 표시하지 않는다.

v3는 구축률 100%를 강제하지 않는다. 단, 성공률 완화가 일반 배치의 실패를 허용하지는 않는다. quiet-safe가 5,040 미만이면 인증 접두 경로를 연장하지 않는다. 별도 100% 기록은 모든 가방의 성공 공급 수가 정확히 5,040일 때만 증가한다. 첫 가방 반사는 허용된 모델 가정이며 실제 모든 반사 입력을 재생했다는 뜻이 아니다.

이전 v2의 기본값은 첫 가방 80% 및 전체 확률 계산 제외, 이후 가방 각각 100%, 전체 100%, 확률 완화 최소 스핀 3이었다. 이 정책의 표시 확률 100%는 첫 가방 포함 100%와 다르다. 기존 실험 화면에는 두 의미를 구분해 표시한다.

한 가방이 인증에 실패하면 인증 접두 경로는 거기에서 끝난다. 이후 실행을 보조 탐색 점수로 남길 수 있지만 이를 인증된 후속 경로나 40L 결과에 더하지 않는다. 우수 개체를 고를 때 인증된 완주와 진행이 보조 점수보다 우선한다. 완성까지의 잠금 수를 미완성 경로에서 지어내지 않는다.

v2와 v3 모두 실패한 첫 가방에서도 전체 실행 그래프와 공급 검사를 끝까지 수행한다. 기존 공개 탐색의 조기 거절은 정확한 통과 판정에 충분하지만, GA에서는 서로 다른 실패 후보가 모두 같은 0점으로 보이는 문제가 있다. 따라서 실제 측정한 quiet-safe 공급 수와 구축 성공 수를 보조 경사로 사용한다. v2의 단일 비교 순서는 인증 완주·완주 비용, 인증 스핀·가방, 첫 실패 가방의 안전·성공 공급 수, 원시 후속 스핀이었다. v3는 선택 best 외의 확률·100%·물리 성과를 별도로 보존한다. 부분 안전 점수가 높아도 모든 공급의 quiet-safe 조건을 충족하기 전에는 통과가 아니다.

## 실행·저장·재개

배치와 검증은 브라우저 CPU Worker의 제한된 작업 단위로 진행한다. 사용자 화면은 원시 진행, 인증 진행, 세대와 개체 위치, 사용 작업량과 실행 상태를 구분한다. 중지 시점의 개체와 검증 단계도 체크포인트에 포함한다.

화면 갱신과 영구 저장은 분리한다. 작은 진행 snapshot은 자주 갱신하되, 자동 체크포인트는 시간 간격을 두고 저장한다. 사용자 저장·일시정지·실행 완료에는 즉시 저장한다. 세대가 빨리 끝났다는 이유로 큰 개체군과 공급 증명을 매 세대 전송하지 않는다.

새 저장 자료는 `ga-v1` 세대로 분리한다. 체크포인트 객체는 R2에, 실행·리비전·체크포인트 참조는 D1에 둔다. 저장 요청은 요청 ID와 예상 리비전을 전달해 재시도 중복과 오래된 탭의 덮어쓰기를 막는다. 체크포인트의 SHA-256은 저장 중 손상 검출에 사용한다. 형식·버전·수치·범위를 검사하며, 파일 해시만으로 실행 증명의 진위를 보장한다고 주장하지 않는다.

이전 `/api/learning/*`는 종료 응답을 돌려준다. 사용자가 폐기하도록 지정한 이전 학습 테이블의 행과 객체는 새 GA 자료를 제외하고 반복 가능한 제한된 단위로 삭제한다. 공개 페이지의 예전 브라우저 전송함도 내용 조회나 전송 없이 정리한다. Supabase의 전송 기능과 사이트 런타임 비밀 값은 활성 경로에서 제거한다.

## 작은 실험과 공정한 비교

처음부터 긴 학습을 예약하지 않는다. 작은 집단과 제한된 세대·작업 예산으로 다음 순서를 따른다.

1. 초기 계수 정책과 실제 배치·공급 인증의 일치 여부를 확인한다.
2. 고정 학습 Seed 집합에서 개체를 진화시킨다.
3. 학습에 쓰지 않은 선택용 Seed에서 후보를 비교한다.
4. 가중치를 고정한 뒤 별도 비교용 Seed에서 초기값·학습 정책·기존 탐색기를 평가한다.
5. 인증 완주, 인증 스핀·가방·미노 수, 원시 스핀, 실행 시간과 실제 작업량을 함께 기록한다.

이 프로젝트의 Seed는 같은 빈 필드 문제에서 후보 선택과 탐색 순서를 바꾸는 반복이다. 서로 다른 게임 문제나 보드 분포에 일반화했다는 근거가 아니다. GA의 단일 탐욕 경로와 장시간 실행한 기존 탐색의 최선 경로를 직접 비교하지 않는다. 고정 정책도 같은 시간 동안 여러 경로를 시도하도록 하고, 반복 중 최고 인증 경로와 실행량을 기록한다. 서로 다른 계산 종류의 작업 단위를 동일 CPU 비용으로 취급하지 않는다.

실험 스크립트, 원시 결과, 성능 보고서와 개인 체크포인트는 공개 저장소에 커밋하지 않는다. 체크포인트는 비공개 작업실에서 보관한다. 기존 테스트는 보존하고 변경 경로에 필요한 실제 실행 검증만 수행한다.

### 네이티브 실행

같은 Rust 코어를 쓰는 `neyra-ga` CLI로 브라우저 밖에서도 CPU 실행을 할 수 있다. 출력은 저장소 밖의 개인 작업 디렉터리에 둔다.

```sh
cargo build --locked --release -p neyra-core --bin neyra-ga
target/release/neyra-ga initializer --config /tmp/neyra-ga-config.json --output /tmp/neyra-initializer.json
target/release/neyra-ga train --config /tmp/neyra-ga-config.json --seconds 120 --output /tmp/neyra-champion.json --checkpoint /tmp/neyra-checkpoint.json --report /tmp/neyra-training.json
target/release/neyra-ga evaluate --model /tmp/neyra-champion.json --seed-start 30000001 --episodes 1024 --seconds 10 --output /tmp/neyra-evaluation.json
target/release/neyra-ga baseline --config /tmp/neyra-ga-config.json --seed 30000001 --seconds 10 --output /tmp/neyra-baseline.json
```

새 v3의 최소 설정 예시는 아래와 같다. 생략한 규칙은 위의 첫 가방 포함·quiet-safe·양의 구축률 계약을 따른다. 시간 예산이 먼저 소진되면 마지막 완료 개체의 champion과 중단 위치가 들어 있는 체크포인트를 각각 저장한다.

```json
{
  "schemaVersion": "neyra-ga-config-v2",
  "populationSize": 12,
  "generations": 8,
  "seed": 20261102,
  "episodesPerGenome": 2,
  "maxPieces": 126,
  "pieceGoal": 119
}
```

재개는 `train --resume /tmp/neyra-checkpoint.json`에 새 출력 경로와 시간 예산을 지정한다. 원래 설정과 난수 상태를 유지하므로 별도 `--config`를 함께 넘기지 않는다. `--work`도 지원하지만 기존 탐색의 한 step과 GA의 작업 단위는 CPU 비용이 같지 않다. 비교에는 경과 시간과 각각의 실제 query 수를 함께 남긴다.

명시적 정책 전환은 `fork --resume OLD --config V3 --checkpoint NEW --output SNAPSHOT`을 사용한다. 원래 run은 수정하지 않고 선택 가중치와 출처 해시만 계승하며 세대·RNG·평가·공급 증명은 새로 시작한다. 학습 모델에서 새 실행을 만들 때는 `train --config V3 --model MODEL`을 사용한다. 새로운 설정으로 원 체크포인트를 그대로 이어받는 기능이 아니다.

## 완료 기준과 다음 결정

**첫 목표 완료**는 quiet-safe 조건 아래 양의 확률로 40L에 도달하는 경로가 있고, 첫 가방 포함 확률과 실제 비용을 함께 제시하며 저장·복원 후 같은 고정 계획을 재검증할 수 있을 때다. **순서에 관계없는 100% 목표**는 모든 가방과 종료 비용 CDF가 정확히 5,040/5,040인 40L 증명을 별도로 요구한다. 두 목표는 같은 완료 표시로 합치지 않는다. 설정된 세대가 끝났거나 원시 스핀이 40에 도달한 것만으로 완료하지 않는다.

**공개 탐색기 대체 준비**는 별도 기준이다. 고정 예산 반복 비교에서 기존 탐색기 대비 완주 또는 인증 진행이 개선되고, 계산비와 실패 양상이 확인되어야 한다. 실험용 GA를 구현했다고 공개 평가기에 자동 적용하지 않는다.

소규모 실험에서 인증 진행이 정체되면 먼저 원인을 나눈다. 원시 스핀도 늘지 않으면 특징·정책 표현·변이 폭을, 원시 성과만 늘면 고정 계획의 공급 가능성과 적합도 설계를 조사한다. 단순히 세대 수만 늘리지 않는다. 현재 다중 경로 탐색은 GA 평가 순서와 기존 검색 계층을 결합하고, 선택한 가중치의 첫 가방을 제안으로 재사용하되 다시 공급 검증한다. 2차 신경망은 계획 조건부 예측으로 검증 순서만 유도한다. 완전한 Go-Explore 또는 PALS를 구현했다는 의미가 아니다. [프런티어 설계](FRONTIER_ENGINE.md)와 [2차 엔진](GUIDE_ENGINE.md)을 참고한다.
