## 자료 전달과 중복 처리

- **전달 완료는 정확한 영수증으로 판단한다.** 동의한 관측은 목적지별 브라우저 outbox에 불변 payload로 저장하고, 연결·페이지 복구 때 같은 내용을 보낸다. IndexedDB를 사용할 수 없는 환경은 메모리 내 재전송만 가능하다. 동의 철회는 미전송 payload를 지운다. 관측 ID·queue ID·payload SHA-256·영수증 상태가 모두 맞아야 완료로 처리한다. trace는 각 identity와 depth가 일치해야 한다. HTTP 성공만으로 부모 전달이나 후손 탐색을 진행하지 않는다.
- **탐색 완료 이력은 유한한 재사용 기록이다.** 동일한 전체 수집 정책과 정확한 물리 방향의 보드에 대해 ACK를 받은 완료 작업 최대 4,096개를 보관한다. 대기·실패 작업은 완료로 넣지 않는다. 저장소 삭제나 오래된 이력의 퇴출까지 막는 전역 중복 제거를 주장하지 않는다. 동일·미러 점유의 학습 중복 제거와 물리 입력 증거는 별도로 유지한다.
- **릴레이와 비공개 저장은 같은 자료를 재입력해도 일관되어야 한다.** Supabase는 원본을 지운 뒤에도 service 전용 identity·digest 영수증을 보존한다. 동일한 재전송은 quota나 새 작업을 추가하지 않고 기존 상태를 돌려주며, 같은 ID에 다른 내용을 넣으면 거부한다. 비공개 저장 확인과 릴레이 원본 삭제는 영수증 계약으로 연결한다. private claim·commit은 정확한 token으로 재시도하고, 살아 있는 lease만 갱신한다. 소유권을 잃으면 계산을 멈춘다. 임시 연결 장애는 재연결하며 사용자 일시정지나 실제 수집 실패와 혼동하지 않는다.
- **실제로 사용한 자료만 fresh에서 소비한다.** 새 자료는 도착 순으로 최대 16개를 고르며, 완료 또는 unchanged 시도의 실제 `orderedRecordIds`만 소비한다. 가장 큰 도착 순번으로 나머지를 사용 처리하지 않는다. 과거 자료 최대 48개의 replay는 의도된 재사용이다. 실패한 묶음은 cooldown 뒤 같은 parent·eligibility에서 최대 두 번 재시도하고, 소진되면 다른 fresh 자료나 바뀐 parent·eligibility를 기다린다. 실패·timeout·cooldown은 학습 완료나 fitted coverage로 세지 않는다. unchanged의 평가 완료도 보존한 부모의 새 학습 계보를 만들어 내지 않는다.

## 1차 학습 완료 기준

정확한 정책 원본은 Learning Studio의 `lib/learning-readiness.ts`에 있는 `neyra-next-bag-readiness-v1`이다.
아래 수는 초기 공학적 승인 기준이며, 이 양만 모으면 일반화가 보장된다는 표본 수 정리가 아니다.
현재 v5 정책의 적격 canonical 입력만 세고 같은 점유·미러는 제외한다. source group도 서로 통계적으로 독립이라는 보장은 없다.

| 항목 | train | validation | test |
| --- | ---: | ---: | ---: |
| 사용 가능한 고유 canonical 보드 | 2,048 | 256 | 256 |
| source group | 32 | 8 | 8 |
| 고정 최종 감사 자료 | — | 256–512 | 256–512 |
| 감사 자료의 양성·0스핀 | — | 각각 32 이상 | 각각 32 이상 |
| 감사 자료의 2스핀 이상 | — | 32 이상 | 32 이상 |
| 감사 자료의 3스핀 이상 | — | 16 이상 | 16 이상 |
| 감사 자료에서 가장 큰 그룹 비중 | — | 25% 이하 | 25% 이하 |

자료 보유량 외에 선택된 모델의 성공한 fitting ancestry에 적격 고유 train 보드 2,048개 이상이 실제로 포함되어야 한다.
반복 epoch·중복 자료·실패 시도나 그대로 선택된 부모로 이 수를 늘리지 않는다.

최종 감사는 소유자가 명시적으로 시작한다. 모델 ID·가중치 hash·정책·eligibility revision·자료 ID와 순서·자료 hash를 고정한다.
중단된 감사는 그 manifest로 이어 간다. 최종 test 그룹은 고정 후보에 한 번 예약하며, 다른 후보를 고르는 데 반복해서 사용하지 않는다.
학습과 epoch 선택에는 test를 쓰지 않는다. 이후 들어온 자료는 이미 측정한 감사 표본을 바꾸지 않으며, 출처 제외는 해당 감사를 무효화한다.

validation과 test가 각각 다음 상한을 모두 통과해야 한다.

| 지표 | 상한 |
| --- | ---: |
| 관측 스핀 MAE | 0.50스핀 |
| MAE의 근사 95% 상단 | 0.75스핀 |
| 발견 확률 Brier | 0.10 |
| Brier의 근사 95% 상단 | 0.15 |
| 평균 부족량 | 0.25스핀 |
| 발견 확률 ECE, 같은 너비의 10구간 | 0.10 |
| 정확히 2스핀·3스핀 이상 층의 MAE, 해당 층이 16개 이상일 때 | 0.75스핀 |
| 같은 다중 스핀 층의 평균 부족량 | 0.50스핀 |
| Rust/WASM 대 TensorFlow.js CPU 발견 확률 최대 절대 오차 | 0.0001 |
| 같은 추론의 스핀 개수 최대 절대 오차 | 0.001 |

근사 상단은 source group 단위의 결정적 cluster bootstrap 1,000회에서 97.5백분위수를 쓴다.
평균 초과량·과소 예측률·스핀 개수별·출발 깊이별 지표도 기록한다.
추론은 소유자의 worker에서 실행하고 서버가 예측 자료로 지표를 재계산한다. 서버가 별도로 추론했다는 의미는 아니다.

| 상태 | 의미 |
| --- | --- |
| `trained` | 실제 fitting으로 선택된 가중치라는 상태다. 완료·일반화 선언이 아니다. |
| `complete` | 자료량·그룹·fitted coverage·고정 validation/test 지표·추론 parity를 모두 통과했다. |
| `deploymentReady` | 학습 완료와 별도로, 같은 규칙·탐색 작업량에서 품질과 CPU 비용을 승인할 근거가 필요하다. 현재 정책에는 그 비교 증거가 없으므로 false다. |

공개 opt-in은 `complete` 이전에도 검증된 trained v5로 실험할 수 있지만, 그 자체로 위 기준을 통과한 것은 아니다.
모델 변경이나 자동 승격의 승인을 대신하지 않는다. 상세 계약은 [LEARNING.md](LEARNING.md)에 있다.

## 다음 모델을 채택하기 전 필요한 확인

1. **한 가방 정밀도와 다양성.** 출발 depth를 올리는 것을 정밀 탐색으로 대신하지 않는다. 여러 출발 깊이를 무작위 평가 구간으로 선택하고, 같은 가방 안의 예산에 따른 최선 스핀 안정성·중복 절감·용량 중단을 확인한다. 전체 가방 도달률과 0스핀 비율을 기록한다. 같은 run/미러를 늘린 수를 독립 표본 수로 쓰지 않는다.
2. **안정적인 분할.** 새 그룹은 기존 학습 입력의 점유 성분을 먼저 따르고, 제약 없는 성분만 해시 배정한다. 결과 보존만으로 생긴 충돌은 해당 입력·후손에 국한한다. 과거 분할과 제외 이벤트를 변경하지 않으며, 잘못된 결과 전용 격리는 원인 감사와 원자적 재확인 뒤 복구 이력을 추가한다. 실제 학습 입력의 충돌은 계속 차단한다. 충분한 train/validation/test 성분이 모이지 않으면 임의 재분할해 학습을 강행하지 않는다.
3. **관측의 재현성.** 수집 소스·규칙·고정 예산 해시와 입력 재생이 맞아야 한다. 클라이언트 보고와 비공개 독립 측정을 구분하고 일부 표본을 재측정해 차이를 기록한다. 부재는 검열된 부재이며 불가능의 정답으로 해석하지 않는다.
4. **한 가방 헤드의 실제 학습.** 같은 v5 정책·작업 범위의 정제 자료로만 학습한다. 입력·한 가방 표지와 원본 재생 증거를 남긴다. 이전 특징을 쓸 때는 출력 헤드를 초기화하고 출처를 남긴다. 존재 예측은 Brier/보정, 개수는 MAE·평균 부족량·평균 초과량·과소 예측률과 출발 깊이별 편향을 확인한다. 과소 예측을 줄였다는 주장은 독립 validation에서 확인해야 한다. 표본 제거가 이전 가중치의 오염까지 취소하지 않으므로, 제외된 학습 계보는 적격 조상 또는 초기 모델로 되돌린다.
5. **짧은 전망의 부작용 확인.** 0스핀 준비 뒤 후속 가방에서 이득을 얻는 경로는 별도 평가 집합으로 확인한다. 한 가방 표지는 현재 관측 범위를 넘겨 합산하지 않으며, 장기적인 준비 가치가 입증됐다고 주장하지 않는다. 새로운 적응형 예산·장기 전망 정책은 별도 버전으로 측정한다.
6. **추론과 탐색의 비용.** 같은 필드·규칙·작업량에서 CPU 추론 비용과 끝까지 이어진 후보 품질을 함께 측정한다. 캐시 hit 수, 피한 실제 작업, 통신량, 벽시계 시간을 구분한다. 계산 공유는 ABBA로 확인하며 새 기준 소스의 품질을 떨어뜨리지 않는 변경을 채택한다.
7. **공개 모델 변경.** 파일의 trained v5 계약·실제 float32 가중치 hash·자료 계보를 검증하고 사용자가 선택한 모델을 run 동안 고정한다. 누락·미학습·계약 오류는 탐색 시작 전에 구조 평가로 돌아간다. snapshot·export에는 실제 활성 평가기와 모델 ID/hash·fallback 사유를 남긴다. 전송 trace도 요청한 설정 대신 실제 평가기와 사용한 모델 출처를 보존한다. 파일 검증만으로 export 이후의 비공개 출처 제외 상태까지 증명할 수 없으므로 현재 적격 계보를 선택해야 한다. 기본 모델 변경은 수치 일치와 별도의 탐색 비교를 거쳐 승인하며, 새 자료나 학습 후보를 자동 승격하지 않는다.

## 구현된 2차 CNN과 남은 40L 채택 조건

별도 `naga-completion-cost-v1` 모델, 실제 완주 경로 검증기, native CPU trainer와 Rust/WASM 추론이 구현되어 있다.
전체 33,441개 매개변수에서 선택한 trained v5의 점유 특징을 재사용하고, pooling 뒤에 `(40 − 완료 스핀) / 40`을 명시적으로 추가한다.
고정 규칙 프로필도 정확히 지정해야 한다. 초기화는 새 progress/output 가중치를 0으로 만들고 원래 모델·가중치 hash·학습 계보를 남기며 미학습 상태를 유지한다.
현재 점유만 받는 1차 헤드에 진행량이나 규칙을 암묵적으로 섞지 않는다.

정답은 입력을 끝까지 재생한 실제 대표 경로의 남은 lock 수다. 같은 입력·남은 목표·정책에서 관측한 최선 비용을 쓰되 원본 증거를 보존한다.
전역 최단 비용·모든 공급에 대한 완주 비용·구축 확률이나 pruning bound라는 뜻이 아니다.
미완성 경로는 exact label로 거부하며, 이미 소비한 미노 수를 최적 비용의 하한으로도 쓰지 않는다.
모델 구조·완주 증거 형식·명령·source-lineage 검증·추론 API는 [COMPLETION_CNN.md](COMPLETION_CNN.md)에 있다.

향후 제어기는 보드 예측으로 탐색 우선순위를 정하되 모든 노드에 최소 확인 예산을 남기고, 실제로 배치한 가방의 스핀 보상을 기록하며, 결과 경계에서 다시 평가하는 방식으로 확장할 수 있다. 실측된 짧은 경로와 잎의 예측값은 구분해 사용한다. 조상 피드백에는 이어진 실제 입력 경로와 유효한 표지 구간이 필요하다. 다른 가방의 보상을 원래 한 가방 표지에 더하지 않는다.

학습된 2차 checkpoint는 기본 제공하지 않으며 공개 탐색에 자동 활성화하지 않는다.
현재 v1은 실제 완주 자료만 받는다. 검열된 부분 관측의 목적함수는 별도 계약이 필요하다.
채택에는 고정된 1차 특징 모델, 다양한 독립 source group의 실제 완주, 남은 목표 범위별 validation/test, 수치 일치와 같은 작업량의 탐색 비교가 필요하다.
이 자료와 비교가 마련되기 전에는 사용자의 미노 제한을 제거하지 않는다.
Transformer는 독립적인 경로 자료와 장기 문맥이 충분해졌을 때 별도로 비교하며, 한 가방 CNN의 수집·검증을 늦추는 선행 조건으로 삼지 않는다.
