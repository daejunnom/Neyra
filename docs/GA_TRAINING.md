# GA 학습과 실제 배치 검증

현재 학습 경로는 작은 배치 평가 계수 벡터를 진화시키는 유전 알고리즘(GA)이다. 목표는 빈 필드에서 고정 가방 계획으로 **40번의 스핀 싱글을 완성**하는 것이다. 우선 상한 안의 완주를 찾고, 이후 사용 미노 수를 줄인다. 기본 선호 목표 119미노와 허용 상한 126미노를 구분한다.

공개 GitHub Pages는 기존 구조 평가기의 일반 탐색을 제공한다. 관측 수집, 비공개 자료 전송, CNN 모델 파일 선택, Supabase 연결은 종료했다. GA 실행과 체크포인트는 기존 소유자 전용 비공개 작업실에 둔다. 이전 CNN 문서는 Git 이력과 오프라인 호환 코드의 설명이며 현재 서비스의 학습 계약이 아니다.

## 왜 작은 GA로 시작하는가

처음부터 정답 보드·완주 경로·신경망 표지를 모으지 않아도 실제 실행 성과로 계수를 비교할 수 있다. 작은 계수 벡터는 CPU에서 평가하기 쉽고 모델·데이터 전송 운영을 줄인다. 다만 유전 알고리즘도 개체마다 배치와 공급 검증을 실행해야 한다. 자료가 필요 없다는 사실이 계산이 적게 든다는 보장은 아니다.

Tetris의 평가 함수 계수를 최적화한 기존 연구는 이 접근의 근거다. 특히 Thiery와 Scherrer의 연구는 특징 선택과 최적화 방법의 중요성을 보여 준다. 이 연구의 cross-entropy 방법은 GA와 다른 알고리즘이며, 일반 Tetris의 성과를 Neyra의 Sonic Drop·스핀 싱글·제한된 홀드 조건에 그대로 옮길 수는 없다. Deep Neuroevolution 연구 또한 GA의 가능성을 보여 주지만, 해당 계산량과 성능은 Neyra의 비용 추정치가 아니다.

## 개체와 배치 환경

개체는 원시 필드·배치 특징에 곱하는 유한한 실수 계수들이다. 초기 계수는 명시적으로 **미학습 초기값**이다. 수동 특징과 초기값은 유도 편향이며, 기존 탐색 결과를 정답으로 모사한 학습 표지가 아니다.

각 배치 단계에서 현재 가방에 남은 모든 미노의 canonical `reachable_locks` 결과를 조사한다. 실제 입력으로 도달한 Sonic Drop 잠금만 허용한다. 충돌, 24행 경계, SRS+, O 스핀 제외, 0줄 일반 배치 또는 정확히 1줄 스핀 싱글이라는 규칙을 유지한다. 기존 공개 탐색의 beam·페이스·형제 후보 비교·구조 예측·futility 가지치기는 GA 후보 생성에 사용하지 않는다.

정책은 열거한 합법 배치의 점수로 다음 수를 선택한다. **가능한 한 수를 모두 평가하는 것과 가능한 전체 수순을 완전 탐색하는 것은 다르다.** 작은 GA가 최적 수순을 보장하거나 비선택적 전수 탐색을 구현했다고 표현하지 않는다.

유전 연산은 우수 개체 보존, 토너먼트 선택, 계수 교차와 변이로 구성한다. 무작위 상태, 세대, 개체와 반복 실행 위치를 저장하므로 중단과 재개를 같은 계산으로 이어갈 수 있다.

현재 `neyra-ga-features-v1`은 24개 계수를 사용한다. 실제 스핀, 최대·합계 높이와 셀 수, 묻힌 빈칸·깊이, 표면 차이와 우물, 행·열 전이, 행의 남은 셀 수, 덮인 빈 공간과 세 모서리 공간, 배치 높이와 접촉, 미노 종류, 막힌 스폰을 정규화해 평가한다. 이러한 기하 특징은 준비 형태를 구분하는 수단이며 실제 스핀이나 공급 성공의 증거는 아니다.

## 원시 성과와 인증 성과

| 기록 | 의미 | 의미하지 않는 것 |
|---|---|---|
| 원시 스핀 | 실제 배치 경로에서 일어난 스핀 싱글 | 모든 공급에서 그 계획을 만들 수 있음 |
| 인증 접두 경로 | 첫 가방부터 연속해서 공급 계약을 통과한 경로 | 이후 원시 경로도 인증됨 |
| 인증 완주 | 목표 스핀과 가방별·누적 확률 및 비용 조건을 통과한 종료 경로 | 전역 최적 미노 수 |
| 세대 완료 | 설정한 개체 평가와 유전 연산 완료 | 학습 목표 달성 |

한 가방은 미노 종류별 고정 logical target과 삭제 이력을 가진 계획으로 만든다. 그 다음 기존 `VerificationJob`의 실제 입력 검사와 5,040개 공급 모델을 사용한다. 모든 공급의 quiet-safe 조건, clear-only hold, 비어 있는 가방별 홀드 시작, 첫 가방 반사 모델, 첫 가방 별도 확률 하한, 이후 가방별 하한과 누적 확률, 마지막 부분 가방의 비용 CDF를 그대로 적용한다.

기본값은 첫 가방 80% 및 전체 확률 계산 제외, 이후 가방 각각 100%, 전체 100%다. 확률 완화 최소 스핀 기본값 3도 유지한다. 첫 가방 반사는 허용된 모델 가정이며 실제 모든 반사 입력을 재생했다는 뜻이 아니다.

한 가방이 인증에 실패하면 인증 접두 경로는 거기에서 끝난다. 이후 실행을 보조 탐색 점수로 남길 수 있지만 이를 인증된 후속 경로나 40L 결과에 더하지 않는다. 우수 개체를 고를 때 인증된 완주와 진행이 보조 점수보다 우선한다. 완성까지의 잠금 수를 미완성 경로에서 지어내지 않는다.

현재 정책 `neyra-ga-sonic-full-locks-fixed-plan-v2`는 실패한 첫 가방에서도 전체 실행 그래프와 공급 검사를 끝까지 수행한다. 기존 공개 탐색의 조기 거절은 정확한 통과 판정에 충분하지만, GA에서는 서로 다른 실패 후보가 모두 같은 0점으로 보이는 문제가 있다. 따라서 실제 측정한 quiet-safe 공급 수와 구축 성공 수를 보조 경사로 사용한다. 비교 순서는 인증 완주·완주 비용, 인증 스핀·가방, 첫 실패 가방의 안전·성공 공급 수, 원시 후속 스핀 순서다. 부분 안전 점수가 높아도 모든 공급의 quiet-safe 조건을 충족하기 전에는 통과가 아니다.

## 실행·저장·재개

배치와 검증은 브라우저 CPU Worker의 제한된 작업 단위로 진행한다. 사용자 화면은 원시 진행, 인증 진행, 세대와 개체 위치, 사용 작업량과 실행 상태를 구분한다. 중지 시점의 개체와 검증 단계도 체크포인트에 포함한다.

화면 갱신과 영구 저장은 분리한다. 작은 진행 snapshot은 자주 갱신하되, 자동 체크포인트는 시간 간격을 두고 저장한다. 사용자 저장·일시정지·실행 완료에는 즉시 저장한다. 세대가 빨리 끝났다는 이유로 큰 개체군과 공급 증명을 매 세대 전송하지 않는다.

새 저장 자료는 `ga-v1` 세대로 분리한다. 체크포인트 객체는 R2에, 실행·리비전·체크포인트 참조는 D1에 둔다. 저장 요청은 요청 ID와 예상 리비전을 전달해 재시도 중복과 오래된 탭의 덮어쓰기를 막는다. 체크포인트의 SHA-256은 저장 중 손상 검출에 사용한다. 형식·버전·수치·범위를 검사하며, 파일 해시만으로 실행 증명의 진위를 보장한다고 주장하지 않는다.

이전 `/api/learning/*`는 종료 응답을 돌려준다. 사용자가 폐기하도록 지정한 이전 학습 테이블의 행과 객체는 새 GA 자료를 제외하고 반복 가능한 제한된 단위로 삭제한다. 공개 페이지의 예전 브라우저 전송함도 내용 조회나 전송 없이 정리한다. Supabase의 전송 기능과 사이트 런타임 비밀 값은 활성 경로에서 제거한다.

## 작은 실험과 공정한 비교

처음부터 긴 학습을 예약하지 않는다. 작은 집단과 제한된 세대·작업 예산으로 다음 순서를 따른다.

1. 초기 계수 정책과 실제 배치·공급 인증의 일치 여부를 확인한다.
2. 고정 학습 Seed 집합에서 개체를 진화시킨다.
3. 학습에 쓰지 않은 선택용 Seed에서 후보를 비교한다.
4. 가중치를 고정한 뒤 별도 비교용 Seed에서 초기값·학습 정책·기존 탐색기를 평가한다.
5. 인증 완주, 인증 스핀·가방·미노 수, 원시 스핀, 실행 시간과 실제 작업량을 함께 기록한다.

이 프로젝트의 Seed는 같은 빈 필드 문제에서 후보 선택과 탐색 순서를 바꾸는 반복이다. 서로 다른 게임 문제나 보드 분포에 일반화했다는 근거가 아니다. GA의 단일 탐욕 경로와 장시간 실행한 기존 탐색의 최선 경로를 직접 비교하지 않는다. 고정 정책도 같은 시간 동안 여러 경로를 시도하도록 하고, 반복 중 최고 인증 경로와 실행량을 기록한다. 서로 다른 계산 종류의 작업 단위를 동일 CPU 비용으로 취급하지 않는다.

실험 스크립트, 원시 결과, 성능 보고서와 개인 체크포인트는 공개 저장소에 커밋하지 않는다. 체크포인트는 비공개 작업실에서 보관한다. 기존 테스트는 보존하고 변경 경로에 필요한 실제 실행 검증만 수행한다.

### 네이티브 실행

같은 Rust 코어를 쓰는 `neyra-ga` CLI로 브라우저 밖에서도 CPU 실행을 할 수 있다. 출력은 저장소 밖의 개인 작업 디렉터리에 둔다.

```sh
cargo build --locked --release -p neyra-core --bin neyra-ga
target/release/neyra-ga initializer --config /tmp/neyra-ga-config.json --output /tmp/neyra-initializer.json
target/release/neyra-ga train --config /tmp/neyra-ga-config.json --seconds 120 --output /tmp/neyra-champion.json --checkpoint /tmp/neyra-checkpoint.json --report /tmp/neyra-training.json
target/release/neyra-ga evaluate --model /tmp/neyra-champion.json --seed-start 30000001 --episodes 1024 --seconds 10 --output /tmp/neyra-evaluation.json
target/release/neyra-ga baseline --config /tmp/neyra-ga-config.json --seed 30000001 --seconds 10 --output /tmp/neyra-baseline.json
```

최소 설정 예시는 아래와 같다. 생략한 규칙은 위의 기본 확률·물리 계약을 따른다. 시간 예산이 먼저 소진되면 마지막 완료 개체의 champion과 중단 위치가 들어 있는 체크포인트를 각각 저장한다.

```json
{
  "schemaVersion": "neyra-ga-config-v1",
  "populationSize": 12,
  "generations": 8,
  "seed": 20261102,
  "episodesPerGenome": 2,
  "maxPieces": 126,
  "pieceGoal": 119
}
```

재개는 `train --resume /tmp/neyra-checkpoint.json`에 새 출력 경로와 시간 예산을 지정한다. 원래 설정과 난수 상태를 유지하므로 별도 `--config`를 함께 넘기지 않는다. `--work`도 지원하지만 기존 탐색의 한 step과 GA의 작업 단위는 CPU 비용이 같지 않다. 비교에는 경과 시간과 각각의 실제 query 수를 함께 남긴다.

## 완료 기준과 다음 결정

**첫 목표 완료**는 기본 계약 또는 명시된 사용자 설정에서 인증된 40L 경로가 있고, 저장·복원 후 같은 고정 계획을 재검증할 수 있을 때다. 설정된 세대가 끝났거나 원시 스핀이 40에 도달한 것만으로 완료하지 않는다.

**공개 탐색기 대체 준비**는 별도 기준이다. 고정 예산 반복 비교에서 기존 탐색기 대비 완주 또는 인증 진행이 개선되고, 계산비와 실패 양상이 확인되어야 한다. 실험용 GA를 구현했다고 공개 평가기에 자동 적용하지 않는다.

소규모 실험에서 인증 진행이 정체되면 먼저 원인을 나눈다. 원시 스핀도 늘지 않으면 특징·정책 표현·변이 폭을, 원시 성과만 늘면 고정 계획의 공급 가능성과 적합도 설계를 조사한다. 단순히 세대 수만 늘리지 않는다. 수순 진화나 제한된 다중 경로 정책은 다음 후보지만, 추가 연산으로 얻는 효과를 별도로 측정한 뒤 도입한다.

- [Such et al., Deep Neuroevolution (2017/2018)](https://arxiv.org/abs/1712.06567): 유전 알고리즘으로 정책 파라미터를 최적화하는 방법, 희소·기만적 보상에서의 한계와 탐색 다양성.
- [기존 탐색 정책](FOCUSED_SEARCH.md), [구조 평가](STRUCTURAL_EVALUATION.md), [기존 설계와 출처](SEARCH_REDESIGN_V2.md): 비교 기준과 유지할 물리·공급 계약.
